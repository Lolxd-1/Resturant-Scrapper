# T10B: Photo swap (choose_alternate) + headless CLI
Wave: 11 · Deps: T10 · Risk: med · Model: sonnet

## Goal
Users can swap any dish's photo to one of its stored alternates (or mark it "needs owner photo") and the three sheets are rebuilt; power users can run the whole pipeline from the command line via `zomato_scrapper.py` (the v1 file name is kept as the CLI entry).

## Contracts
- Produces: `choose_alternate(engine: Engine, job_dir: Path, sku: str, alt_index: int | None, uploader: Uploader | None) -> DishResult` in studio/pipeline.py; `main(argv: list[str] | None = None) -> int` in zomato_scrapper.py.

## Steps
1. choose_alternate: load results.json; find the row by sku (KeyError -> ValueError(f"Unknown SKU {sku}")). alt_index None -> status needs_photo, reason "Marked by you: needs owner photo", keep the old pick as alternate 0 (so it can be restored), clear local_image/hosted_url/zomato_img. Otherwise alt = alternates[alt_index] (IndexError -> ValueError("No such alternate")): fetch_full(alt["zomato_img"], engine.http) (None -> ValueError("That photo could not be downloaded")); save images/<sku>.jpg; upload when the job options had upload True and uploader is given (UploadError propagates as ValueError with its message); the previous pick (if any) is inserted into alternates in place of the chosen one; update item_name/restaurant/restaurant_url/zomato_img/tier/confidence/source/image_size/hosted_url; status recomputed (ready / needs_price / error). Only this SKU changes (size variants are NOT changed automatically). Write results.json, rebuild outputs with build_outputs, update job.json summary; return the DishResult.
2. zomato_scrapper.py: replace the whole v1 file with a thin CLI:
   `python zomato_scrapper.py --menu-excel M.xlsx --vendor "Name" [--city pune] [--zomato-url URL] [--sku-prefix HFC] [--out DIR] [--no-upload] [--strict] [--no-live-search] [--budget 250]`.
   Uses build_engine(load_settings()); uploader from settings keys, else env IMGBB_API_KEY as one key labelled "env"; --no-upload -> uploader None and opts.upload False. job_dir = --out or OUTPUT_DIR / new_job_id(vendor). Prints stage events as `[stage] label` and dish events as `SKU  status  name -> item @ restaurant`, then the three output paths and the summary. Returns 0 when status done, 1 otherwise. `if __name__ == "__main__": sys.exit(main())`. Module docstring explains the command in 5 lines.
3. Force UTF-8 console output at CLI start: `sys.stdout.reconfigure(encoding="utf-8", errors="replace")` when available.

## Test cases (tests/test_pipeline_cli.py)
- TC1 swap: after a TC1-style job (reuse helpers from tests/test_pipeline.py by importing them), choose_alternate(sku, 0) changes zomato_img to the alternate, puts the old pick into alternates, rebuilds READY (file mtime changes, P column has the new URL).
- TC2 mark none: alt_index None -> row needs_photo, READY no longer contains the SKU, PENDING does.
- TC3 errors: unknown SKU -> ValueError; alt index 99 -> ValueError.
- TC4 CLI no-upload: monkeypatch `studio.pipeline.build_engine` to return the fake engine; `main(["--menu-excel", path, "--vendor", "Test Cafe", "--no-upload", "--out", str(tmp)])` returns 0 and the three xlsx files exist; output contains "UPLOAD_READY".
- TC5 CLI bad file -> returns 1 and prints the menu error.
