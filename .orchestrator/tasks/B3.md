# B3: Pipeline AI — enrich dishes (diet + photo names) and AI photo judge
Wave: 6 · Deps: B1 A5 · Risk: high · Model: opus

## Goal
When a Gemini key is set, (1) dishes without Diet/Photo Names get them from one Gemini call per 120 dishes before matching, and (2) a new "judge" stage lets Gemini look at the candidate photos (batches of 25 dishes, up to 4 photos each) to drop wrong/branded photos, pick the best clean one, and rescue dishes the CLIP check wrongly vetoed. Without a key, or when Gemini fails, behaviour is exactly A5's.

## Context
User ruling: look-alikes always need human approval. So the judge may promote a rung-0 candidate to ready only on verdict "same"; anything "similar", and every rung >= 1 photo, stays "review". Free-tier quota is tiny: never more than ceil(dishes/120) enrich calls and ceil(judged groups/25) judge calls per job; on any GeminiError stop calling Gemini for the rest of the job (one warning). Prompts/schemas: studio/prompts.py (ENRICH_*, JUDGE_*), client: studio/gemini.py.

## Steps
1. Enrich (in `_Run.read`, after `read_menu`, before parsing dishes/rungs): rows needing help = rows with empty photo_names or empty diet. If gemini available and any: for batches of 120 send `text_part(json.dumps([{"id": row.row, "name", "category", "description"}], ensure_ascii=False))` with ENRICH_SYSTEM/ENRICH_SCHEMA (max_output_tokens 32768). Fill only empty fields: diet if in ("veg","nonveg","egg"); photo_names cleaned like reader (strings, strip, dedup, drop equal-to-name, <= 3, <= 80 chars); description only if the row's is empty (<= 300). say(f"AI filled details for {n} dishes"). GeminiError -> warning "AI helper unavailable: {msg}" (once per job), continue.
2. `_verify_group` stores `g.kept` = its final sorted kept list (whichever rung set it used; [] when nothing kept).
3. New stage `judge()` between verify() and photos() in run_job. Skip when gemini is None/unavailable. For each non-failed group whose rows[0].source is not "own"/"chain": candidates = `g.kept[:4]`, or when g.kept is empty the rescue set: rung-0 exact/strong candidates from g.cands not marked bad, top 4. Skip groups with no candidates. Batches of 25 groups: fetch 300px thumbs (`imaging.fetch_thumb_ex`, ThreadPoolExecutor like verify); drop candidates whose thumb fails. parts: one intro text_part, then per group i (1-based) `text_part(f"Dish {i}: {display} | category: {category or '-'} | diet: {diet or 'unknown'}")` and per photo label A-D `text_part(f"Dish {i} photo {label}:")` + `image_part(thumb)`. Call generate_json(JUDGE_SYSTEM, parts, JUDGE_SCHEMA, max_output_tokens=16384).
4. Apply per group (ignore groups/labels missing from the answer — keep A5's result for them): ok = clean and verdict != "different"; order by (verdict "same" first, quality desc, original order). Respect `self.used_images` exactly like _verify_group (prefer an ok candidate not used by another group).
   - rung-0 candidates: best "same" -> pick it, lookalike False, search_name "". Only "similar" -> pick best, lookalike True, search_name = g.q.display, reason "Similar photo — approve it or search again". None ok -> clear the pick (item_name, restaurant, restaurant_url, zomato_img, tier, confidence, source = "" / 0.0; alternates []), lookalike False, reason f"AI found no matching photo ({n} checked)".
   - rung >= 1 candidates: best ok -> pick, lookalike True (keep search_name); none -> clear as above with reason f"AI found no matching look-alike photo ({n} checked)".
   - alternates = the other ok candidates in that order (max 4). Pick dicts via `_cand_dict`.
   - say(f"AI checked photos for {k} dishes") after the stage.
5. GeminiError (incl. quota) -> warning f"AI photo check unavailable: {msg}" once; keep A5's decisions for all unjudged groups.
