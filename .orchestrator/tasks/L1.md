# L1: Lexicon gaps, retrieval tie-break, safer word splitting
Wave: 5 · Deps: A5 · Risk: med · Model: sonnet

## Goal
Fix three measured causes of missed matches (orchestrator recon on the user's real menus, 2026-10-07) without changing any other behaviour.

## Context (evidence)
1. "Uthappa" (Vithai menu, 11 dishes) is not a synonym of UTTAPAM, so "Onion Uthappa" has no dish type and matches nothing.
2. Serving words stay as dish tokens: "Paper Masala Dosa (Family)" -> token "family"; "Chicken Tandoori (Single Piece)" -> "single"; "Extra Pav (Pair)" -> "pair"; "Shubham Special Unlimited Thali" -> "unlimited".
3. `PoolIndex.retrieve` ranks by summed idf only. For the one-token query "Palak" (veg) hundreds of "Palak X" items tie with the exact item "Palak", and `heapq.nlargest(600, ...)` keeps the earliest by position, so the exact "Palak" item (present in the real pool) is never scored.
4. `Speller._split` splits unknown words into any vocab words of >= 3 letters with df >= 5. On the 800k-item pool, junk 3-letter fragments qualify: "tartara" -> "tart ara", "dingari" -> "ding ari", "vithai" -> mangled. Real glued words seen in menus split into >= 4-letter parts (anda+kari, boil+anda, paneer+lajij) or use a MISSPELLINGS key (green+pis).

2. matcher.py `retrieve`: rank the kept (weight, pos) pairs by `weight - 0.01 * len(self._tokens[pos] - query_toks)` (fewer unmatched item tokens first), then `-pos` as today. One-line comment why. Nothing else changes.
3. spelling.py `_split`: a part shorter than 4 letters is allowed only if it is a MISSPELLINGS key or a lexicon word (`self._lexicon`); otherwise that split is skipped.
