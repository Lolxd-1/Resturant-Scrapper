# T14: Seed pool builder tool (cache import + resumable multi-city crawl + export)
Wave: 15 · Deps: T04, T05 · Risk: med · Model: sonnet

## Goal
`tools/build_seed_pool.py` builds the shipped photo pool `data/seed_pool.jsonl.gz` from (a) the cached Zomato pages in `zcache/`, (b) the legacy `data/pairs.json`, and (c) a polite, resumable crawl of cuisine listings across many cities — so every fresh install starts with a large, multi-city pool.

## Contracts
- CLI: `python tools/build_seed_pool.py [--work-db PATH] [--from-cache DIR] [--from-pairs PATH] [--crawl] [--cities a,b,c|all] [--cuisines x,y|all] [--max-restaurants N] [--workers N] [--export PATH]`
- Functions (importable for tests): `import_cache(store: PoolStore, cache_dir: Path) -> int`, `import_pairs(store: PoolStore, pairs_path: Path) -> int`, `crawl(store: PoolStore, client: ZomatoClient, cities: list[str], cuisines: list[str], max_restaurants: int, workers: int, log=print) -> int`, `export_seed(store: PoolStore, out_path: Path) -> dict` (returns {"restaurants", "items", "bytes"}).

## Steps
1. Work DB default: `tools/.seed_work.sqlite` (git-ignored: add nothing to .gitignore; write it under `%LOCALAPPDATA%\MenuStudio\seed_work.sqlite` instead via config.home_dir()). It is a normal PoolStore.
2. import_cache: for each `*order.html` in cache_dir: parse_state -> parse_menu(state, fallback_url derived from the file name is NOT reliable: use state data only) -> store.upsert_menu. Return items imported.
3. import_pairs: legacy entries `{"name","img","rest"}`; group by rest slug; skip slugs whose restaurant already exists in the store (match by url ending with "/" + slug); url = https://www.zomato.com/<city>/<slug> where city is unknown -> use "legacy" as the city segment; diet = "nonveg"/"egg" from item_proteins(name) (EGG only -> "egg"), else "unknown"; category and menu_name "". Upsert as RestaurantMenu(res_id="legacy-"+slug, name=slug.replace("-", " ").title(), ...).
4. crawl: for each city in cities, for each cuisine: urls = client.listing(city, cuisine); collect in order; skip urls already in the store (menu_fetched_at not None); fetch menus with ThreadPoolExecutor(workers) (Http throttling keeps it polite); upsert each; log progress every 25 restaurants ("[city/cuisine] 125 restaurants, 9,812 items"); stop at max_restaurants new restaurants. ZomatoBlocked -> log "Blocked by Zomato; waiting 10 minutes" and sleep 600 s once, then continue; a second block -> stop cleanly (the work DB keeps progress, so re-running resumes).
5. export_seed: stream every restaurant with >= 1 item, sorted by res_url, items sorted by (category, name); write gzip (compresslevel 9) JSONL lines in the exact seed format with "d" truncated to 200 chars; skip items without img; return stats. Print stats.
6. `main()` wires the CLI; default with no flags prints help.

## Test cases (tests/test_seed_tool.py)
- TC1 import_cache on a tmp dir with two synthetic order pages (make_pages.state_html) -> both restaurants and their items stored with categories and diets.
- TC2 import_pairs: legacy file with 2 slugs, one of which exists from the cache -> only the other is imported; "Chicken Tikka" gets diet "nonveg", "Paneer Tikka" "unknown".
- TC3 crawl with FakeSession: 2 cities x 1 cuisine listing pages linking 3 restaurants (one shared) -> 3 menus fetched once each; max_restaurants=2 stops after 2.
- TC4 export_seed -> gzip JSONL whose lines have exactly the keys r, rn, c, n, cat, m, d, dt, i; PoolStore.ensure_seeded on the exported file imports the same item count.
- TC5 blocked twice -> crawl returns without raising (sleep injected/monkeypatched).
