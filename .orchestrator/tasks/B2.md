# B2: Menu photo reader (Gemini) + CLI --menu-image
Wave: 6 · Deps: B1 · Risk: med · Model: sonnet

## Goal
1-8 menu photos -> a list of clean dish items -> `menu_extract.xlsx` that `read_menu` (with A2's Diet/Photo Names columns) reads back. The CLI can start a job from photos.

## Context
Prompts and schemas are data in `studio/prompts.py` (MENU_READER_SYSTEM, MENU_SCHEMA) — use them as-is, do not edit them. Gemini client: `studio/gemini.py` (`Gemini.generate_json`, `text_part`, `image_part`, `GeminiError`). Phone photos are often rotated by EXIF and are 3000-4000 px; Gemini tiles images at 768 px, so 3072 px long side keeps small menu text readable.

## Contracts (produce exactly)
```text
studio/reader.py:
  IMAGE_EXTS = (".jpg", ".jpeg", ".png", ".webp")
  MAX_PHOTOS = 8
  class MenuReadError(Exception)                       # plain-English message
  prepare_image(data: bytes) -> bytes                  # EXIF-rotated RGB JPEG (quality 90), long side <= 3072
  read_menu_images(gemini, images: list[bytes]) -> tuple[str, list[dict]]
      # (restaurant_name, items); item keys: name, category, description, price (float|None), diet ("veg"|"nonveg"|"egg"|""), photo_names (list[str])
  write_extract(items: list[dict], path: Path) -> Path # sheet "Menu": Item Name | Category | Description | Price | Diet | Photo Names
```

## Steps
1. `prepare_image`: PIL open (failure -> MenuReadError("Could not open one of the photos. Use JPG or PNG.")), `ImageOps.exif_transpose`, convert RGB, `thumbnail((3072, 3072), LANCZOS)`, save JPEG q90.
2. `read_menu_images`: 0 photos -> MenuReadError("Add at least one menu photo."); > MAX_PHOTOS -> MenuReadError("Upload at most 8 photos per menu."). parts = `[text_part(f"{n} menu photo(s). Read every dish on every photo.")]` then for each photo `text_part(f"Photo {i}:")`, `image_part(prepare_image(b))`. Call `gemini.generate_json(MENU_READER_SYSTEM, parts, MENU_SCHEMA, high_res=True)` (GeminiError propagates). Clean each item: name stripped (skip empty); variant -> if non-empty and its lowercase text is not already in the name, name becomes f"{name} ({variant})"; category stripped or "Menu"; price: number or numeric string > 0 -> float, else None; description stripped, <= 300 chars; diet kept only if in ("veg","nonveg","egg") else ""; photo_names: strings, stripped, dedup case-insensitive, drop ones equal to the name (case-insensitive), at most 3, each <= 80 chars. Drop exact duplicate (name, price) items. No items -> MenuReadError("No dishes found on the photo(s). Try a sharper, straight photo of the menu."). Log the dish count and gemini.last_model.
3. `write_extract`: openpyxl, bold header, column widths, Diet shown as "Veg"/"Non-Veg"/"Egg"/"" , Photo Names joined with "; ", Price as int when whole.
4. CLI: replace `--menu-excel` required arg with a required mutually exclusive group: `--menu-excel PATH` | `--menu-image PATH [PATH ...]`. For images: settings.gemini_key empty -> print "Add your free Gemini API key in Settings (or config/settings.json) to read menu photos." and return 2; else `Gemini(settings.gemini_key, cache_dir=ai_cache_dir())`, read files, `read_menu_images`, job_dir.mkdir, `write_extract(items, job_dir / "menu_extract.xlsx")`, print "Read N dishes from M photo(s)", then run the job on that file. MenuReadError/GeminiError -> print message, return 2.
