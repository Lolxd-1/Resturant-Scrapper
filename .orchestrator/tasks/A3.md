# A3: Swiggy dish search client, pool merge-insert, host-aware image URLs
Wave: 1 · Deps: none · Risk: med · Model: sonnet

## Goal
A `SwiggyClient` turns one Swiggy dish search into pool items with photos; the pool can merge those items in without deleting anything; image download works for both Zomato and Swiggy photo URLs.

## Context
Zomato lacks many common dishes. Swiggy's public dish search (probed 2026-10-07) returns 60-200 dishes with clean catalog photos per query. Two trimmed real responses are committed in `tests/fixtures/swiggy/` (dish_search_egg_roast.json, dish_search_mushroom_uttapam.json). Response layout: `data.cards[*].groupedCard.cardGroupMap.DISH.cards[*].card.card`; entries whose `@type` ends with `DishGroup` have `restaurant.info` {id, name, slugs{restaurant, city}} and `dishes[*].info` {id, name, category, description, imageId (may be null), isVeg (1 = veg, missing = not veg), price}.
Photo URLs: original = `https://media-assets.swiggy.com/swiggy/image/upload/<imageId>`; 300px thumb = insert `fl_lossy,f_auto,q_auto,w_300,h_300,c_fill/` after `upload/` (both verified live).

## Steps
1. swiggy.py `parse_dish_search`: walk as described in Context using `.get()` with dict/list type checks; skip any malformed card (never raise). Per DishGroup: res_id = str(info["id"]), name = info["name"]; url = `f"https://www.swiggy.com/city/{slugs['city']}/{slugs['restaurant']}-rest{res_id}"` when both slugs exist, else `f"https://www.swiggy.com/restaurants/{res_id}"`; menu city = slugs city or the `city` argument. Per dish with a non-empty name and imageId: PoolItem(item_id=0, name=stripped name, category=info category or "", menu_name="Swiggy", description=whitespace-collapsed description[:300], diet="veg" if isVeg == 1 else "nonveg", img_url=IMG_BASE + imageId, res_id, res_name=name, res_url=url, city, chain_key=chain_key(name)). Merge groups of the same url into one RestaurantMenu (cuisines=""); dedupe (name, img_url) per restaurant; return only menus with items, in first-seen order.
2. `SwiggyClient.search_dishes`: unknown city -> return [] without a request. Else `self.http.get(SEARCH_URL, params={"lat": lat, "lng": lng, "str": query, "submitAction": "ENTER", "selectedPLTab": "DISH"})`. `ZomatoBlocked` raised by Http (403) -> raise `SwiggyBlocked(str(exc))`. None response, non-JSON, non-dict, or `statusCode` present and != 0 -> []. Else `parse_dish_search(data, city)`. Log like zomato.py (`log = logging.getLogger("studio.swiggy")`).
3. zomato.py `_throttle`: treat `"media-assets.swiggy.com"` like `"b.zmtcdn.com"` (quarter interval). Nothing else in zomato.py changes.
4. store.py `add_items(menu)`: under the lock and one transaction: `INSERT INTO restaurants (...) VALUES (?, '?'...) ON CONFLICT(res_url) DO NOTHING` with res_id, name, city, cuisines, chain_key(name), fetched_at=time.time(), source='swiggy'; read existing `(name, img_url)` pairs for that res_url (use menu.url as-is — do NOT pass it through canonical_res_url, which is Zomato-only); insert only new pairs; return the inserted items as PoolItems with their new item_id (cursor.lastrowid) and the menu's res fields. If `_items_cache` is not None, extend it with the inserted items (do not reset it: rebuilding the cache costs ~4 s on the real pool).
5. imaging.py: `thumb_url(url)`: strip query; Swiggy (`startswith(IMG_BASE)`) -> IMG_BASE + "fl_lossy,f_auto,q_auto,w_300,h_300,c_fill/" + rest; otherwise base + THUMB_SUFFIX. `full_url(url)`: strip query. Use them in `fetch_thumb_ex` and `fetch_full_ex` instead of the inline string ops (behaviour for Zomato URLs identical).
