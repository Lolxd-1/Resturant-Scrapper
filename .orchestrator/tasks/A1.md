# A1: Matcher rule fixes (category-derived head, mocktail)
Wave: 1 · Deps: none · Risk: med · Model: sonnet

## Goal
Two over-strict rules stop common dishes from matching. Fix exactly these two, keep every existing matcher test green.

## Context
- "Tandoori Chicken" in menu category "Tandoori Kebabs" gets `q.head = "KEBAB"` from the category (text.py `item_head`). A pool item "Tandoori Chicken" whose category is "Chicken Kebab" also gets head KEBAB, and `_item_facts` (matcher.py:41-48) adds the token "KEBAB" to the item's tokens. `_score_variant` then rejects it twice: `"item is a KEBAB"` (matcher.py:149-150) and, if that passes, `"extra KEBAB"` (extra head token, matcher.py:165-167). Both sides agree it is a kebab-type dish, so it must match.
- "Mango Mocktail" (category "Menu Item") vs pool "Mango Mocktail" in category "Mocktails": the pool item gets head MOJITO from CATEGORY_HEAD_HINTS["mocktail"] (lexicon.py:517) but the word "mocktail" in a dish NAME is not a token synonym of MOJITO, so the query has no head -> `"item is a MOJITO"`.
