# A2: Optional "Diet" and "Photo Names" menu columns
Wave: 1 · Deps: none · Risk: low · Model: sonnet

## Goal
`read_menu` reads two optional columns, Diet and Photo Names, into new MenuRow fields. Files without them behave exactly as today.

## Context
The menu photo reader (later task) and a copy-paste Gemini prompt will produce Excel files with these extra columns. "Photo Names" lists look-alike dish names that would show the same photo (e.g. "Paneer Pizza; Veg Pizza"); "Diet" is veg / non-veg / egg.

- `studio/menu.py`: `_ROLE_ORDER`, `_ROLE_SYNONYMS`, `_normalize_header_cell`, `_detect_header`, `_parse_rows` (MenuRow construction ~line 236).
- `tests/test_menu.py` and `tests/conftest.py::make_xlsx`.

## Write-set
- modify: studio/models.py

- test: tests/test_menu.py

## Contracts
- Produces: `MenuRow.diet: str = ""` and `MenuRow.photo_names: list[str] = field(default_factory=list)` — add both AFTER `warnings` (keep field order valid).
- Produces: `parse_diet(value: object) -> str` and `parse_photo_names(value: object) -> list[str]` in studio/menu.py (public, next to `parse_price`).

## Steps
1. models.py: add the two MenuRow fields with a trailing comment each, matching the file's style.
2. menu.py `_ROLE_SYNONYMS`: add
   - `"diet": {"diet", "veg non veg", "veg nonveg", "veg or non veg", "food type", "veg non veg egg"}`
   - `"photo_names": {"photo names", "photo name", "photo search names", "search names", "look alike names", "lookalike names"}`
   and append `"diet", "photo_names"` to `_ROLE_ORDER` (after "price"). Header cells are matched after `_normalize_header_cell` ("Veg/Non-Veg" -> "veg non veg").
3. `parse_diet(value)`: non-str -> "". Normalize: lower, every non-letter -> space, collapse spaces, strip. Map:
   - "veg", "vegetarian", "v", "pure veg", "green" -> "veg"
   - "non veg", "nonveg", "non vegetarian", "nv", "red" -> "nonveg"
   - "egg", "eggetarian", "contains egg" -> "egg"
   - anything else -> "".
4. `parse_photo_names(value)`: non-str -> []. Split on `;`, `|` or newline; strip each with whitespace collapsed; drop empty; drop case-insensitive duplicates keeping the first; cut each to 80 chars; keep at most 4.
5. `_parse_rows`: read `columns.get("diet")` / `columns.get("photo_names")` and pass `diet=parse_diet(_cell(row, diet_idx)), photo_names=parse_photo_names(_cell(row, photo_idx))` to MenuRow. No other behaviour change (section-header detection, warnings, dedup stay as is).

## Test cases
- TC1: xlsx header `["Item Name","Category","Description","Price","Diet","Photo Names"]`, row `["Paneer Pizza (Single Cheese)","Pizza","",120,"Veg","Paneer Pizza; Veg Pizza"]` -> rows[0].diet == "veg", rows[0].photo_names == ["Paneer Pizza","Veg Pizza"], price 120.0, category "Pizza".
- TC2: header `["Dish","Section","Rate","Veg/Non-Veg","Photo Search Names"]`, row `["Tandoori Lollipop","Starters",220,"Non-Veg","Chicken Lollipop | Tandoori Chicken"]` -> diet "nonveg", photo_names ["Chicken Lollipop","Tandoori Chicken"].
- TC3: parse_diet table: "VEG"->"veg", "Vegetarian"->"veg", "non-veg"->"nonveg", "Non Vegetarian"->"nonveg", "NV"->"nonveg", "Egg"->"egg", "eggetarian"->"egg", "maybe"->"", None->"", 5->"".
- TC4: parse_photo_names: "A; B;; a" -> ["A","B"]; "  x  |  y\nz " -> ["x","y","z"]; "1;2;3;4;5" -> ["1","2","3","4"]; None -> []; "" -> []; 12 -> [].
- TC5: an existing 4-column file (reuse the layout of `test_tc1_v1_layout_happy`) -> every row has diet "" and photo_names [].
