# B4: Web app — Gemini key, menu-photo upload + preview, Gemini-website prompt
Wave: 7 · Deps: A6 B1 B2 B3 · Risk: med · Model: sonnet

## Goal
From the existing web app the user can save a Gemini key, upload 1-8 menu photos, see the read dishes in the preview (with Diet and Photo Names), download the extract, and run the job; or copy the Gemini-website prompt when they have no key/quota. Jobs use the key saved at run time.

## Context
- `studio/gemini.py`: `Gemini(key, cache_dir=ai_cache_dir())`, `check_key()`, `GeminiError`. `studio/reader.py`: `IMAGE_EXTS`, `MAX_PHOTOS`, `read_menu_images`, `write_extract`, `MenuReadError`. `studio/prompts.py::manual_prompt()`. `Settings.gemini_key` (B1). `Engine.gemini` attribute and the "judge" stage (B3).
- Reading a menu takes 30-120 s (one Gemini call); run it off the event loop (`await asyncio.to_thread(...)`).

## Steps
1. Settings API: `_settings_view` adds `"gemini_set": bool, "gemini_tail": last 4 chars or ""`; PUT accepts `"gemini_key"`: absent -> keep current; "" -> clear; otherwise strip and store (reject length < 20 or whitespace inside with 400 "That doesn't look like a Gemini key"). Keep all existing fields/behaviour. New `POST /api/settings/test-gemini` body `{"key"?}` (empty -> saved key) -> `{"ok", "message"}` from `Gemini(key).check_key()`.
2. Worker._run: before run_job set `self.engine.gemini = Gemini(settings.gemini_key, cache_dir=ai_cache_dir()) if settings.gemini_key else None`.
3. `POST /api/menu/preview`: parameter becomes `file: list[UploadFile] = File(...)` (one Excel still works unchanged). If every file's extension is in IMAGE_EXTS: no saved key -> 400 "Add your free Gemini key in Settings to read menu photos, or use the Gemini website prompt below."; more than MAX_PHOTOS -> 400; read bytes (each <= MAX_UPLOAD_BYTES else 413); `name, items = await asyncio.to_thread(read_menu_images, gemini, datas)`; MenuReadError/GeminiError -> 400 with its message; `write_extract(items, uploads_dir / f"{upload_id}.xlsx")`; then parse that file exactly like an Excel upload. Mixed images + other files, or several non-image files -> 400 "Upload either menu photos or one Excel file". Response adds `"extracted": bool`, `"restaurant_name": str`, and each row adds `"diet"` and `"photo_names"`.
4. `GET /api/uploads/{upload_id}/extract` -> the extracted xlsx (404 unless UPLOAD_ID_RE matches and the file exists). `GET /api/prompt` -> `{"prompt": manual_prompt()}`. FILE_KINDS gains `"menu"` -> the job's menu file (job["menu_file"]) for download as "Menu sheet".
5. UI New job: the file input accepts `.xlsx,.xlsm,.csv,.jpg,.jpeg,.png,.webp` and `multiple`; with photos show a progress line "Reading your menu with Gemini… this takes up to 2 minutes" and disable Run until done; if the preview response has restaurant_name and the vendor field is empty, prefill it; preview table shows Diet and Photo Names columns when any row has them; link "Download extracted sheet" when extracted. A collapsible card "No Gemini key or quota? Use the Gemini website": steps (1 open gemini.google.com, 2 attach the menu photo(s), 3 paste this prompt, 4 Export to Sheets -> download .xlsx, 5 upload it here), a read-only textarea with GET /api/prompt text, and a Copy button (navigator.clipboard, fallback select()).
6. UI Settings: "Gemini API key (free)" field (masked: "Saved key ending ••••abcd" + Replace/Remove), link text "Get a free key at aistudio.google.com/apikey" (plain text or a link), Test button -> /api/settings/test-gemini.
7. UI STAGES: insert `["judge", "AI check", "AI photo check"]` between "verify" and "photos". Hero/download area adds "Menu sheet" when files.menu exists (server summary already lists files; if not, use the new kind directly).
