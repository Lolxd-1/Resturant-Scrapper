# T15: Live evaluation tool (dry-run jobs + visual contact sheets)
Wave: 16 · Deps: T10, T10B · Risk: low · Model: sonnet

## Goal
`tools/eval_menus.py` runs real (network) dry-run jobs — no ImgBB upload — over a folder of menu files and produces, per menu, a contact-sheet image set and an HTML page so a reviewer can audit every chosen photo quickly, plus a coverage summary. The orchestrator uses it to measure precision (AC13).

## Contracts
- CLI: `python tools/eval_menus.py --menus DIR [--out DIR] [--only NAME] [--city pune] [--budget 250] [--strict]`; default out `eval/out`.
- Menu vendor name: file stem with "_" -> " " (e.g. `H_Food_Cafe.xlsx` -> "H Food Cafe"); an optional sidecar `<stem>.json` may override {"vendor": str, "city": str, "zomato_url": str}.
- Functions: `contact_sheets(results: list[DishResult], job_dir: Path, out_prefix: Path, per_sheet: int = 20) -> list[Path]`, `html_report(results, job_dir, out_path: Path) -> Path`.

## Steps
1. For each menu (sorted): job_dir = out/<stem>; run_job(engine, menu, job_dir, JobOptions(vendor, city, zomato_url, upload=False, strictness, live_budget_menus=budget), uploader=None, on_event=print-stage-lines). One Engine for all menus (build_engine(load_settings())).
2. contact_sheets: grid 5 columns x 4 rows of 300x300 tiles + a 90 px caption under each (PIL default font is acceptable; try `ImageFont.truetype("arial.ttf", 13)` first): line 1 `SKU  dish name` (truncate 38 chars), line 2 `-> zomato item @ restaurant` (truncate 44), line 3 `tier conf source`. Tiles without a photo show a grey box with "NO PHOTO: <reason>". Save JPEG quality 85 as `<out_prefix>_01.jpg`, `_02.jpg`...
3. html_report: a self-contained HTML table (image via relative path to job_dir/images) with the same fields; written to out/<stem>/review.html.
4. Summary printed and written to out/summary.csv: menu, total, ready(photo), needs_photo, needs_price, errors, coverage%.
5. .gitignore: append `eval/` (vendor menus and eval outputs must never be committed).
