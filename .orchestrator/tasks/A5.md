# A5: Pipeline — look-alike rungs, Swiggy search, review status, search/approve helpers
Wave: 3 · Deps: A1 A3 A4 · Risk: high · Model: opus

## Goal
Every dish is matched against its own name (rung 0) and then its look-alike names (rungs 1..n). Rung-0 behaviour is unchanged. A dish whose photo comes from a rung >= 1 is a look-alike: photo downloaded, NOT uploaded, status "review" until approved. Swiggy dish search runs before the Zomato crawl. Two helpers serve the review UI: `search_photos` and `approve_dishes`.

## Context
Precision is the product's promise: never change which rung-0 photo is chosen or how rung-0 candidates are gated. Look-alikes only ever create "review" dishes (a human approves). Swiggy (studio/swiggy.py, A3) returns RestaurantMenu lists; `PoolStore.add_items` (A3) merge-inserts and returns new PoolItems. `lookalike_names` and the new model fields come from A4; `MenuRow.diet/photo_names` from A2.

## Steps
1. read(): per row, `q = parse_dish(...)` as today; if `row.diet` -> `q = dataclasses.replace(q, diet=row.diet)`. Look-alike names = `row.photo_names or lookalike_names(fixed)` (fixed = speller-corrected name). Each name -> `parse_dish(speller.fix_text(n), speller.fix_text(row.category), "", display=n)` with the same diet override; drop rungs with no variants or whose base_key equals q.base_key or an earlier rung's. `_Group(key, q, rungs)` stores `self.rungs = [q, *rungs]` (first row of a group decides). DishResult gets `diet=row.diet or (q.diet if q.diet != "unknown" else "")`, `photo_names=[rung.display for rung in rungs]`.
2. `_Run.ranked_group(g)`: rank each rung with `self.ranked(rq)`, set `c.rung = i`, skip img_urls already seen in an earlier rung, concatenate (rung 0 first). `ranked()` additionally sets `c.source = "swiggy"` when `c.item.res_url.startswith("https://www.swiggy.com/")`. match() and search() use ranked_group.
3. `_confident(cands)`: consider only `c.rung == 0` candidates (same rule as today on that subset).
4. search(): if `not opts.live_search` return. Unresolved groups as today. New first pass `_swiggy_search(unresolved)` when `engine.swiggy` is set: cities = first 2 of `dict.fromkeys([opts.city, "pune", "mumbai", "bangalore"])` that are in SWIGGY_CITIES; per group, for rung index i in 0..min(3, len(rungs))-1: query `_query_text(rung.raw)` in each city (cache by (text, city); stop all Swiggy work after 300 requests per job), `engine.add_items` every returned menu, then `g.cands = self.ranked_group(g)`; stop this group when rung 0 is confident or some candidate with rung == i has tier exact/strong. Progress via `self.stage("search", ...)`. `SwiggyBlocked` -> append warning "Swiggy is limiting requests from this PC; continuing without it." once, stop Swiggy for the job. Then the existing Zomato rounds run for groups still not confident, unchanged except they use ranked_group, and they must still run when Swiggy is disabled; the `engine.blocked`/budget early-return now applies only to the Zomato part.
5. verify: rung-0 candidates (`[c for c in g.cands if c.rung == 0][:8]`) go through EXACTLY today's screening and gating. Only if that keeps nothing: take the first rung r >= 1 that has exact/strong candidates, up to 4 of them, screen them with: thumb/embedding as today, food_ok, head margin >= HEAD_SOFT_VETO using `g.rungs[r].head`, tier exact/strong only, `c.consensus` among these, `c.vision = text_sim(..., g.rungs[r].raw)`, `final = _combine_scores`. Pick as today (used_images rule applies). For a rung >= 1 pick: rows get `lookalike=True`, `search_name=g.rungs[r].display`, `reason=f"Look-alike photo ({search_name}) — approve it or search again"`; alternates = the other kept candidates of that rung. For a rung-0 pick: `lookalike=False`, `search_name=""`. `_cand_dict` adds `"rung": c.rung`. Without vision, mirror today's no-vision branch for the look-alike set (food/head checks skipped).
6. photos(): unchanged download logic (imaging is host-aware now). Emit review rows after their photo is saved (today's emit filter would hide them forever because they are never uploaded).
7. upload(): skip rows with `lookalike and not approved`.
8. `_settle`: after the needs_price check add `elif r.local_image and r.lookalike and not r.approved: status "review"` (keep r.reason if set, else "Look-alike photo — approve it or search again"). `_summarize` adds "review".
9. choose_alternate: picking an alternate sets `r.approved = True` and `r.lookalike = bool(alt.get("rung"))`; marking "needs owner photo" sets `lookalike = approved = False`.
10. `search_photos`: read r under job_lock; outside the lock build `q = parse_dish(query, r.category, "", display=query)` (+ diet override from r.diet); empty variants -> `ValueError("Type a dish name to search for")`; rank on the pool; if fewer than 4 exact/strong and engine.swiggy: search Swiggy for `_query_text(query)` in the job's city (job.json options.city if in SWIGGY_CITIES else "pune") and "mumbai", add_items, re-rank (SwiggyBlocked -> ignore). Keep exact/strong/close, skip bad images, top 8. Under the lock, reload results, set `r.alternates = [dict(_cand_dict(c), rung=max(c.rung, 1)) for c in top]`, `r.search_name = query`, write results.json, return r. The current photo is not changed.
11. `approve_dishes`: under job_lock: for each sku in `skus` whose status is "review": if job option upload is true, upload the local image (`uploader is None` -> `ValueError(NO_KEY_MESSAGE)`; UploadError -> ValueError(str)), set hosted_url; `approved=True`; status/reason cleared then `_settle`. Unknown sku -> ValueError(f"Unknown SKU {sku}"). Write results.json, set job["sheets_stale"] = True (like choose_alternate with rebuild=False). Return the updated DishResults.
