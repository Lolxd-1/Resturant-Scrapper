# T11: Local web server (FastAPI) + app.py entry point
Wave: 12 · Deps: T10, T10B · Risk: med · Model: sonnet

## Goal
`studio/server.py` exposes the pipeline to the browser UI through a small JSON + SSE API, runs jobs in ONE background worker thread (never inside a request), keeps settings (ImgBB keys) persistent and never returns full keys; `app.py` starts it on a free local port, opens the browser, and detects an already-running instance.

## Contracts
- `create_app(engine_factory=None, output_dir: Path = OUTPUT_DIR, config_path: Path = CONFIG_PATH, start_worker: bool = True) -> FastAPI`; engine_factory: zero-arg callable returning an Engine (default `lambda: build_engine(load_settings(config_path), on_status=...)`).
- Endpoints (JSON unless noted), all under 127.0.0.1:
  - GET /api/health -> {"ok": true, "app": "menustudio", "version": studio.__version__}
  - GET /api/system -> {"ready": bool, "status": str, "pool_items": int, "pool_restaurants": int, "vision": bool, "vision_reason": str, "keys": int, "version": str, "active_job": str|null}
  - GET /api/settings -> {"imgbb_keys": [{"id": int, "label": str, "tail": str, "enabled": bool}], "strictness", "live_search", "live_budget_menus", "default_city", "cities": [slug list from zomato.CITIES sorted]}
  - PUT /api/settings body same shape; key entries: {"id"?: int, "label": str, "key"?: str, "enabled": bool}; an entry with "id" and no/empty "key" keeps the stored key at that index; a new entry must have a key of 20-64 chars [A-Za-z0-9] (400 "That doesn't look like an ImgBB key"); returns GET shape.
  - POST /api/settings/test-key {"key"} or {"id"} -> {"ok": bool, "message": str}
  - POST /api/menu/preview (multipart field "file", max 10 MB -> 413) -> {"upload_id", "file_name", "sheet", "rows": [{"row","name","category","description","price","warnings"}], "categories": [{"name","count"}], "warnings", "errors"}; the file is stored at output_dir/"_uploads"/<upload_id><ext> (upload_id = uuid4 hex).
  - POST /api/jobs {"upload_id","vendor","city","zomato_url","sku_prefix"} -> {"id"}; 400 "Enter the restaurant name" when vendor blank; 400 "Upload the menu again" for unknown upload_id; options from current settings (strictness, live_search, live_budget_menus; city defaults to settings.default_city).
  - GET /api/jobs -> [{"id","vendor","status","created","summary"}] newest first
  - GET /api/jobs/{id} -> {"job": job.json, "results": results.json list or [], "active": bool}
  - GET /api/jobs/{id}/events?after=<n> -> text/event-stream: replays buffered events with index > after as `id: <n>\ndata: <json>\n\n`, then streams new ones; `: keepalive\n\n` every 15 s; closes after a done/error event or when the job is not active and the buffer is exhausted.
  - POST /api/jobs/{id}/cancel -> {"ok": true}
  - POST /api/jobs/{id}/resume -> {"ok": true} (re-queues run_job on the same job dir with options from job.json; 409 if active)
  - POST /api/jobs/{id}/dishes/{sku}/choose {"alt_index": int|null} -> DishResult dict; 400 with the ValueError message
  - GET /api/jobs/{id}/files/{kind} kind in ready|pending|report -> file download (Content-Disposition with the real file name)
  - GET /api/jobs/{id}/images/{sku}.jpg -> image/jpeg
  - GET /api/jobs/{id}/zip -> application/zip with the 3 xlsx + images/
  - GET / -> studio/web/index.html (Cache-Control: no-store); static files mounted at /static from studio/web/
- `app.py`: `main(argv: list[str] | None = None) -> int` with `--port` (default 8501; if busy pick a free port), `--host` (default 127.0.0.1), `--no-browser`, `--self-test`.

## Steps
1. Validation helpers: job id regex `^\d{8}-\d{6}-[a-z0-9-]{1,40}$`, sku regex `^[A-Z0-9]{1,6}-\d{3,4}$`, kind whitelist; anything else -> 404. Resolve paths and assert they stay inside output_dir.
2. Engine: built lazily in a daemon thread at startup (status strings: "Loading photo pool…", "Preparing visual check (first run downloads ~600 MB)…", "Ready"); failures -> status "Engine failed: <msg>", ready False. `/api/system` reads the live status.
3. Worker: one daemon thread + queue.Queue of job ids; waits for the engine; builds `Uploader(settings.imgbb_keys, store=engine.store)` when keys exist else None; calls run_job with on_event -> EventBus.publish(job_id, ev) and a per-job threading.Event for cancel. Exceptions are caught, logged and published as an error event.
4. EventBus: per job a list of events (cap 5000, oldest dropped but indexes keep increasing) + threading.Condition; `subscribe(job_id, after)` generator used by the SSE endpoint (runs in a thread via starlette's iterate_in_threadpool or an async generator polling the condition with asyncio.to_thread; must not block the event loop).
5. On startup: jobs whose job.json status is "running" but are not active (crash/restart) are shown with status "interrupted" in GET /api/jobs (do not rewrite their files).
6. Settings: load/save via studio.config with config_path; never include the full key in any response or log.
7. index.html placeholder: a minimal valid HTML page titled "Menu Studio" that loads /static/app.css and /static/app.js (T12 replaces it; T11 only needs GET / to serve it).
8. app.py (replace v1 entirely): configure logging (INFO to console, format "%(asctime)s %(message)s", datefmt "%H:%M:%S"); single-instance: read home_dir()/"server.json" {"port","pid"}; if GET http://127.0.0.1:<port>/api/health answers {"app":"menustudio"} within 2 s -> open the browser there (unless --no-browser), print "Menu Studio is already running at <url>", return 0. Else choose the port, write server.json, start a thread that polls /api/health then opens the browser once, and run `uvicorn.run(create_app(), host, port, log_level="warning")`. Print a friendly banner: "Menu Studio is running at <url> — keep this window open. Close it to stop." `--self-test`: create_app(start_worker=False) with a TestClient-free check: start uvicorn in a thread on a free port, GET /api/health and /, print "SELF-TEST OK", shut down, return 0 (1 on failure). `if __name__ == "__main__": sys.exit(main())`.

## Test cases (tests/test_server.py; fastapi.testclient.TestClient; engine_factory returns a fake Engine built like tests/test_pipeline.py; output_dir and config_path in tmp_path)
- TC1 /api/health ok; GET / returns HTML containing "Menu Studio".
- TC2 settings: PUT two keys -> GET returns tails only (assert the full key string appears nowhere in the response text); PUT with {"id":0,"label":"Main"} and no key keeps key 0; invalid key -> 400.
- TC3 preview: upload an xlsx made with make_xlsx -> rows and categories counted; a .xls -> errors list non-empty; 11 MB body -> 413.
- TC4 job flow: POST /api/jobs -> id; poll GET /api/jobs/{id} until status done (timeout 30 s) -> results present; GET files/ready returns an xlsx (starts with b"PK"); GET zip contains the 3 xlsx.
- TC5 events: GET /api/jobs/{id}/events after completion replays events including a "done" event and closes.
- TC6 validation: GET /api/jobs/../../etc/files/ready -> 404; unknown kind -> 404; vendor blank -> 400.
- TC7 choose: POST choose with alt_index null -> row status needs_photo.
- TC8 app.py main(["--self-test"]) returns 0.
