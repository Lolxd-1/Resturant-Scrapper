# T08: ImgBB multi-key uploader with rotation, cooldown and dedupe
Wave: 8 · Deps: T05 · Risk: high · Model: sonnet

## Goal
`studio/hosting.py` uploads JPEG bytes to ImgBB using a pool of user keys: round-robin rotation, invalid keys disabled, rate-limited/failing keys cooled down, and identical bytes never uploaded twice (sha256 cache in the pool DB). It never logs or returns a full API key.

## Context
Verified ImgBB responses (2026-09-27): invalid/missing key -> HTTP 400 `{"status_code":400,"error":{"message":"Invalid API v1 key.","code":100},"status_txt":"Bad Request"}`. Success -> 200 `{"data":{"url": "...", "display_url": "...", ...},"success":true,"status":200}`. ImgBB free keys hit rate limits under bulk use (messages contain "rate limit" / "Too many"; can come as 400 or 429). SmartBiz accepts ibb.co/imgbb.com links. freeimage.host is NOT used (broken public key).

## Contracts
- Produces: `IMGBB_URL = "https://api.imgbb.com/1/upload"`, `class UploadError(Exception)`, `class Uploader` with `__init__(self, keys: list[ImgbbKey], *, http_post=requests.post, store: PoolStore | None = None, sleep=time.sleep, clock=time.monotonic)`, `upload(self, jpeg: bytes, name: str) -> str`, `key_states(self) -> list[dict]` (each `{"label": str, "tail": str, "state": "ok"|"cooldown"|"disabled", "last_error": str}`), and module function `test_key(key: str, *, http_post=requests.post) -> tuple[bool, str]`.

## Steps
1. Only keys with enabled=True and non-empty key are used; no usable keys -> `upload` raises UploadError("No ImgBB API key saved. Add one in Settings.").
2. `upload(jpeg, name)`: h = sha256 hex; if store and store.get_upload(h) -> return it (no HTTP). Name: slugify `name` to `[a-z0-9-]`, max 60 chars.
3. Rotation: keep an index; each upload starts at the next key in round-robin order and skips disabled keys and keys still cooling down (cooldown_until > clock()). If every usable key is cooling down, sleep until the earliest cooldown ends (max 120 s per wait) and try again; total attempts across keys <= 3 * number of keys + 2.
4. Per attempt: `http_post(IMGBB_URL, data={"key": key, "name": name}, files={"image": (name + ".jpg", jpeg, "image/jpeg")}, timeout=60)`. Classify:
   - network exception -> key cooldown 5 s * consecutive failures (max 60 s); next key.
   - JSON with success true and data.url -> URL = data["display_url"] if it starts with http else data["url"]; must start with "https://" (convert "http://" to "https://"); store.put_upload(h, url, "imgbb"); return.
   - error message containing "Invalid API" (case-insensitive) or error code 100 -> key state "disabled" for the life of this Uploader, last_error "Invalid key".
   - status 429 or message matching /rate|too many|limit/i -> cooldown 60 s, last_error "Rate limited".
   - status >= 500 or non-JSON body -> cooldown 10 s, last_error "Server error <status>".
   - other 4xx (e.g. "Invalid image") -> do NOT blame the key; raise UploadError("ImgBB rejected the image: <message>") immediately.
5. When attempts run out -> raise UploadError("All ImgBB keys failed: " + "; ".join(f"{label}: {last_error}")).
6. `key_states()`: tail = last 4 chars of the key.
7. `test_key(key)`: upload a 32x32 generated JPEG with `data={"key": key, "expiration": 60}`; return (True, "Key works") on success; (False, "Invalid key") for the invalid-key error; (False, "Rate limited — try again later") for rate limits; (False, "Could not reach ImgBB: <short>") for network errors; (False, <message>) otherwise.
8. No log line, exception message or return value may contain a full key (tests assert this).

## Test cases (fake http_post returning FakeResponse from tests/conftest.py; fake sleep/clock)
- TC1 happy: one key, success JSON -> returns https display_url; store records it; a second upload of the same bytes makes no HTTP call.
- TC2 rotation: 3 keys, 3 uploads of different bytes -> the keys used are k1, k2, k3 in order.
- TC3 invalid key: k1 returns the verified invalid-key JSON, k2 succeeds -> URL returned; key_states shows k1 "disabled"; a later upload never calls k1.
- TC4 rate limit: k1 returns 429 -> cooldown; k2 used; after the fake clock advances 61 s k1 is usable again.
- TC5 all keys invalid -> UploadError whose message lists every label and contains no full key.
- TC6 network exceptions on every key then success on retry after cooldown (fake sleep advances fake clock) -> URL returned.
- TC7 image rejected (400 "Invalid image source") -> UploadError immediately, keys not disabled.
- TC8 no enabled keys -> UploadError with the Settings message.
- TC9 test_key: success, invalid, rate-limit, network error map to the exact tuples in step 7.
- TC10 "http://" url in response is returned as "https://".
