# T13: One-click Windows launcher (fresh PC, no admin) + README
Wave: 14 · Deps: T11 · Risk: high · Model: sonnet

## Goal
A team member who has never installed anything double-clicks `RUN_ME.bat` and, after a one-time setup, gets Menu Studio open in their browser. No Python/Node/admin rights needed; re-runs start in seconds; a second double-click while running just opens the browser; every failure prints a plain-English fix and waits for a key.

## Context
v1 RUN_ME.bat required a manual Python install and broke on nested quotes. New approach (PLAN D7): `RUN_ME.bat` only calls `scripts/setup.ps1`, which downloads `uv` (single exe from GitHub releases) to get a private Python 3.12 + venv under `%LOCALAPPDATA%\MenuStudio`, installs the locked requirements only when requirements.txt changes, then runs `app.py`. Fallback when uv cannot be downloaded: an existing Python 3.10-3.13 (never the `WindowsApps` store stub) with `-m venv` + pip. The app folder may be inside OneDrive and have spaces in its path.

## Steps
1. `RUN_ME.bat` (CRLF line endings; ASCII only; no nested quotes inside parenthesised blocks):
```
@echo off
setlocal
title Menu Studio
cd /d "%~dp0"
powershell -NoProfile -ExecutionPolicy Bypass -File "%~dp0scripts\setup.ps1" %*
if errorlevel 1 goto failed
exit /b 0
:failed
echo.
echo Menu Studio could not start. Read the message above, fix it, then double-click RUN_ME.bat again.
pause
exit /b 1
```
2. `scripts/setup.ps1` (Windows PowerShell 5.1 compatible: no `&&`, no ternary, no `??`; `$ErrorActionPreference = "Stop"`; `[Net.ServicePointManager]::SecurityProtocol = [Net.SecurityProtocolType]::Tls12`; `$ProgressPreference = "SilentlyContinue"` for fast downloads). Param block: `[switch]$CheckOnly` (set up everything, then run `app.py --self-test` instead of the app and exit with its code), `[switch]$NoBrowser`.
   - `$AppDir` = parent of the script folder; `$HomeDir` = $env:MENUSTUDIO_HOME if set else "$env:LOCALAPPDATA\MenuStudio"; create it. Set env for children: MENUSTUDIO_HOME=$HomeDir, UV_PYTHON_INSTALL_DIR="$HomeDir\python", UV_CACHE_DIR="$HomeDir\uv-cache", UV_LINK_MODE="copy", PYTHONUTF8="1".
   - Banner lines: "Menu Studio — first start takes 3-8 minutes (downloads ~700 MB once). Later starts take seconds."
   - Step [1/4] Already running? If "$HomeDir\server.json" exists, read port; try `Invoke-WebRequest http://127.0.0.1:<port>/api/health -UseBasicParsing -TimeoutSec 2`; if content contains "menustudio": unless CheckOnly, `Start-Process "http://127.0.0.1:<port>/"`, write "Menu Studio is already open in your browser.", exit 0.
   - Step [2/4] Python: `$Py = "$HomeDir\venv\Scripts\python.exe"`. If missing: get uv: `$Uv = "$HomeDir\tools\uv.exe"`; if missing download `https://github.com/astral-sh/uv/releases/latest/download/uv-x86_64-pc-windows-msvc.zip` to "$HomeDir\tools\uv.zip" (Invoke-WebRequest -UseBasicParsing, 2 retries), `Expand-Archive -Force`, locate uv.exe inside (it may be in a subfolder) and move it to $Uv. Then `& $Uv venv --python 3.12 --seed "$HomeDir\venv"`. If any uv step fails: find a fallback Python: try `py -3.12`, `py -3.11`, `py -3.13`, `py -3.10` (via `& py -3.12 -c "import sys;print(sys.executable)"`), then `python` from `Get-Command python -All` whose Source does not contain "WindowsApps" and whose version is 3.10-3.13; create the venv with `& <python> -m venv "$HomeDir\venv"`. If nothing works: print "Could not set up Python automatically. Check your internet connection and run RUN_ME.bat again. If your office network blocks GitHub, install Python 3.12 from https://www.python.org/downloads/ (tick 'Add python.exe to PATH') and try again." and exit 1.
   - Step [3/4] Libraries: `$Req = "$AppDir\requirements.txt"`; hash = (Get-FileHash $Req -Algorithm SHA256).Hash; stamp file "$HomeDir\venv\.req-hash". If different or missing: when uv exists `& $Uv pip install --python $Py -r $Req`; else `& $Py -m pip install --disable-pip-version-check -r $Req`. Check `$LASTEXITCODE`; on failure print "Could not download the libraries. Check your internet connection and run RUN_ME.bat again." and exit 1. Write the hash on success.
   - Step [4/4] Start: CheckOnly -> `& $Py "$AppDir\app.py" --self-test`; exit with $LASTEXITCODE. Else `Set-Location $AppDir`; `& $Py "$AppDir\app.py"` plus `--no-browser` when requested; exit with its exit code. Write "The first start also downloads the visual-check model (~600 MB) in the background; the app shows progress." before starting.
   - Wrap the body in try/catch: catch prints "Unexpected problem: <message>" and exits 1. All output via Write-Host with simple colours (Cyan headings, Green OK, Yellow warnings, Red errors).
3. README.md (rewrite for the team, plain English): what it does (1 paragraph + the 5-stage flow), "Use it" (3 steps: download ZIP from GitHub -> extract -> double-click RUN_ME.bat; first start 3-8 min), "Settings: ImgBB keys" (how to get a free key at https://api.imgbb.com/, add 2-4 keys, why), "Your menu Excel" (columns, flexible headers, blank prices OK, categories -> SmartBiz Product Category), "What you get" (UPLOAD_READY, PENDING, Photo Report + owner checklist; where files are saved: `outputs/`), "How accuracy works" (own/chain photos first, whole-Zomato search across 20 cities, strict matching rules, visual check, never a wrong photo on purpose — uncertain dishes go to the owner checklist), "Troubleshooting" (black window closes, port busy, no internet, antivirus warnings, "Zomato is limiting requests", reset: delete %LOCALAPPDATA%\MenuStudio), "For developers" (`python -m venv .venv`, `pip install -r requirements-dev.txt`, `pytest`, CLI usage of zomato_scrapper.py, tools/build_seed_pool.py, tools/eval_menus.py), "Never commit" (config/, outputs/, vendor menus).
4. `.devcontainer/devcontainer.json`: keep the image and extensions; replace the Streamlit commands with `"updateContentCommand": "pip3 install --user -r requirements.txt"` and `"postAttachCommand": {"server": "python app.py --no-browser --host 0.0.0.0 --port 8501"}`; keep port 8501 forwarding.
5. Delete `.streamlit/secrets.toml.example` (Streamlit is gone).
