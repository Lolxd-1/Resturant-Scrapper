# T12: Apple-grade web UI (single page, no build step, works offline)
Wave: 13 · Deps: T11 · Risk: med · Model: opus

## Goal
`studio/web/` is a polished single-page app that a non-technical team member can use without instructions: start a job from a menu Excel, watch it work live, review photos by category, swap/remove photos, download the sheets, manage ImgBB keys. It must look and feel like a first-party Apple app (macOS Ventura/visionOS System Settings, Photos, Notes) while running in Chrome/Edge on Windows.

## Read first
- `studio/server.py` (every endpoint and JSON shape — the UI must use exactly these)
- `studio/models.py` (DishResult fields), `studio/pipeline.py` (event types and stage ids: read, source, match, search, verify, photos, upload, build)

## Design system (follow exactly)
- Fonts: `font-family: -apple-system, BlinkMacSystemFont, "SF Pro Text", "Segoe UI Variable Text", "Segoe UI", Inter, system-ui, sans-serif`; display titles use "SF Pro Display", "Segoe UI Variable Display". Large title 34/41 weight 700 letter-spacing -0.02em; title2 22/28 600; body 15/20; caption 12/16 secondary colour. Tabular numbers for counts (`font-variant-numeric: tabular-nums`).
- Colour tokens on :root, light: --bg #f5f5f7, --surface #ffffff, --surface-2 #fbfbfd, --glass rgba(255,255,255,0.72), --text #1d1d1f, --text-2 #6e6e73, --separator rgba(60,60,67,0.12), --accent #0071e3, --accent-press #0062c4, --green #34c759, --orange #ff9f0a, --red #ff3b30, --shadow 0 1px 2px rgba(0,0,0,.04), 0 8px 24px rgba(0,0,0,.06). Dark (prefers-color-scheme: dark AND :root[data-theme=dark]): --bg #000, --surface #1c1c1e, --surface-2 #2c2c2e, --glass rgba(28,28,30,0.72), --text #f5f5f7, --text-2 #98989d, --separator rgba(84,84,88,0.45), --accent #0a84ff.
- Radii: cards 18px, inputs/buttons 10px, pills 999px, photo tiles 14px. Spacing scale 4/8/12/16/24/32/48.
- Glass: sidebar and sticky toolbar use `background: var(--glass); backdrop-filter: saturate(180%) blur(20px)`.
- Motion: 200-300 ms `cubic-bezier(.2,.8,.2,1)`; tiles fade+scale in as results stream; respect `prefers-reduced-motion`.
- Controls: primary button filled accent with white text, secondary = tinted (accent 10% bg); segmented control for filters; iOS-style toggle switches; text fields with 1px separator border and 3px accent focus ring (`box-shadow: 0 0 0 3px color-mix(in srgb, var(--accent) 30%, transparent)`).
- Icons: inline SVG (SF Symbols-like strokes 1.75px), no icon fonts, no external requests at all (no CDN, no Google Fonts).

## Layout and views (hash router: #/new, #/job/<id>, #/history, #/settings)
- App shell: left sidebar (240px, glass) with app icon + "Menu Studio", nav items New Job / History / Settings, and at the bottom a system status pill from GET /api/system ("Ready · 412k photos", "Preparing visual check…" with spinner, or orange "No ImgBB key — add one" linking to Settings). Content area max-width 1180px, centred. Below 900px width the sidebar becomes a bottom tab bar; 390px phone width must not scroll horizontally.
- New Job: large title "New job"; a card with (1) big drop zone (dashed 1.5px separator, hover/drag accent tint, accepts .xlsx/.xlsm/.csv, click to browse) which uploads to /api/menu/preview immediately; (2) fields Restaurant name (required), City (select: "Any city" + cities from settings, default settings.default_city), SKU prefix (auto-filled from the name like HFC, editable), "Zomato link (optional)" with helper text "Paste the restaurant's own Zomato page for exact photos". After preview: a menu summary card: "101 dishes · 9 categories", category chips with counts, warnings list (orange, collapsible), errors (red, blocks Start), a compact scrollable table (Dish, Category, Price with "—" for missing). Primary button "Find photos" (disabled until a valid preview and name). If no ImgBB key is saved show an inline banner with a "Add key" button opening Settings (the job can still start; rows will show "error" status).
- Job view (#/job/<id>): header with vendor name, status pill (Running / Done / Cancelled / Failed / Interrupted), Cancel (running) or Resume (interrupted/failed/cancelled). While running: a horizontal stage tracker of the 8 stages (done = green check, current = accent with subtle pulse, pending = grey) with the current stage label and a thin progress bar; live counters (Photos found / Need owner photo / Need price). Results area: segmented filter [All, Ready, Needs photo, Needs price, Errors]; search field; sections per category (sticky category headers with counts); a responsive grid of dish tiles (min 180px): square photo (object-fit cover, lazy, from /api/jobs/<id>/images/<sku>.jpg), or a placeholder glyph with the reason for no-photo tiles; below: dish name (2 lines max), price, a confidence dot (green >= 0.85, orange < 0.85, grey none) and source caption ("Chain photo", "Own menu", "From <restaurant>"). Clicking a tile opens a detail sheet (centred modal with blur backdrop, Esc/overlay closes): big photo, dish name, category, price, status + reason, "Matched: <Zomato item> @ <restaurant>" with link, confidence, tier; alternates row (thumbnails from the Zomato CDN urls with the `?fit=around%7C300%3A300&crop=300%3A300%3B%2A%2C%2A` suffix) each with "Use this photo" -> POST choose then refresh tile; "Needs owner photo" destructive-tinted button -> POST choose null. When done: a summary hero card (coverage ring/percentage, counts) and a download bar: "Upload-ready sheet" (primary), "Pending sheet", "Report", "Everything (.zip)". Live updates via EventSource(/api/jobs/<id>/events?after=<last>) with automatic reconnect using the last event id; on load, render from GET /api/jobs/<id> first.
- History: list of past jobs (card rows): vendor, date, status pill, "96 of 101 ready", chevron -> job view. Empty state illustration + "Start your first job".
- Settings: grouped inset lists like iOS Settings. Section "ImgBB keys" explaining "Add 2–4 free keys from api.imgbb.com. Menu Studio rotates between them and skips a key that hits its limit." Each key row: label, •••• tail, enabled toggle, "Test" (shows spinner then ✓/✕ message inline), delete (confirm). "Add key" row expands a form (Label, Key with paste). Section "Matching": Strictness segmented [Balanced (recommended), Strict], "Search all of Zomato live" toggle, "Search depth" select (Quick 80 / Standard 250 / Deep 600 menus), "Home city" select. Save happens automatically on change (PUT /api/settings) with a small "Saved" toast.
- Toasts: bottom-centre glass capsule, auto-hide 2.5 s. Errors from the API shown as toasts with the server message.
- Accessibility: all controls keyboard reachable, visible focus, aria-labels on icon buttons, alt text on photos (dish name), colour is never the only signal (icons + text on status pills), contrast AA.

## Steps
1. Write index.html (semantic shell, `<meta name="viewport" content="width=device-width,initial-scale=1">`, `<meta name="color-scheme" content="light dark">`, favicon icon.svg, loads /static/app.css and /static/app.js as a module), app.css (tokens + components + responsive rules), app.js (router, API client with JSON error handling, views, EventSource handling, small DOM helper `h(tag, attrs, ...children)`; no frameworks). Escape every server string (use textContent, never innerHTML with data).
2. icon.svg: a simple rounded-square app icon (accent gradient) with a white fork-and-camera glyph.
3. Run the app to check it: `.venv/Scripts/python app.py --no-browser --port 8765` in the background is NOT allowed to be left running; instead verify with the headless screenshot commands in Verify (they start and stop the server themselves via the helper script below).
4. app.js is one self-contained file with NO import/export statements (so `node --check` can parse it); load it with `<script type="module" src="/static/app.js">`.
5. Create no other files. Keep app.js under ~1,400 lines and app.css under ~900 lines.
