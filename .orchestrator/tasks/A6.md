# A6: Review screen — endpoints + web UI
Wave: 4 · Deps: A5 · Risk: med · Model: sonnet

## Goal
In the job page the user can (1) filter "Review" dishes, (2) approve one look-alike or all of them, (3) type a dish name, search, and pick a photo for any finished dish (review, needs photo, ready). Sheets rebuild after changes.

## Context
A5 added status "review" (look-alike photo saved locally, not uploaded), DishResult fields `diet, photo_names, search_name, lookalike, approved`, and helpers in studio/pipeline.py: `search_photos(engine, job_dir, sku, query) -> DishResult` (fills `alternates` with up to 8 candidates, each dict has item_name, restaurant, restaurant_url, zomato_img, tier, confidence, source, rung) and `approve_dishes(engine, job_dir, skus, uploader) -> list[DishResult]` (sets job sheets_stale). `choose_alternate` already exists (POST .../choose) and now marks the dish approved. Photo URLs can be Zomato (`b.zmtcdn.com`, thumb = url + THUMB_SUFFIX) or Swiggy (`https://media-assets.swiggy.com/swiggy/image/upload/<id>`, thumb = insert `fl_lossy,f_auto,q_auto,w_300,h_300,c_fill/` after `upload/`).

## Steps
1. server.py `POST /api/jobs/{id}/dishes/{sku}/search` body `{"query": str}`: same guards as choose_dish (job exists, SKU_RE, engine ready 503, job active 409 with the same message). Empty/whitespace query -> 400 "Type a dish name to search for". `search_photos(...)`; ValueError -> 400 with its message. Return `dish_result_to_dict(result)`. No rebuild (status does not change).
2. server.py `POST /api/jobs/{id}/approve` body `{"skus": [str, ...]}` or `{"all": true}`: guards as above (validate each sku with SKU_RE, 400 on bad). `all` -> every sku whose status is "review" in results.json. Build uploader like choose_dish. Under `job_lock(job_dir)`: `approve_dishes(...)` (ValueError -> 400), then `worker.request_rebuild(id)`. Return `{"results": [dish dicts]}`.
3. app.js constants: `DISH_STATUS.review = ["Review look-alike", "orange", "photo"]`; FILTERS gets `["review", "Review"]` right after "ready"; add `function thumbUrl(url)` implementing the two thumb rules (Context) and use it for alternate thumbnails instead of `alt.zomato_img + THUMB_SUFFIX`. `sourceCaption`: source "swiggy" -> `From ${r.restaurant} (Swiggy)` (or "From Swiggy").
4. Tiles: for status review show in the meta line `Look-alike: ${r.search_name}` instead of the source caption.
5. Detail sheet (`openDetail`), when the job is not running:
   - review: primary button "Approve this photo" -> POST approve {skus:[sku]}; on success update `results`, close sheet, re-render list + hero, toast "Approved".
   - every finished dish: a search row (input prefilled with `r.search_name || (r.photo_names && r.photo_names[0]) || r.name`, button "Search photos"; Enter submits) -> POST search -> replace `results` entry and re-open the sheet so the new "Other photos" show; empty result -> toast "No photos found — try a simpler name". Disable the button while searching (spinner like `choose`).
   - keep the existing "Other photos" list + "Use this photo" + "Needs owner photo" behaviour.
6. Hero (finished job) and counts: add `review` to `counts()`, a stat "Look-alikes to review", and, when review > 0, a button "Approve all look-alikes (N)" -> POST approve {all:true} -> reload the job via the existing `recheck`/`load` path, toast "Approved N photos".
7. app.css: only what the new search row needs (reuse existing classes first).
