# T06: Matcher — pool index, precision-first scoring, tiers, golden test set
Wave: 6 · Deps: T03, T05 · Risk: high · Model: opus

## Goal
`studio/matcher.py` decides, for a menu dish (`DishQuery`) and a Zomato item (`PoolItem`), whether the item's photo shows the SAME dish, as a tier (exact / strong / close / reject) plus a 0..1 text score, and retrieves/ranks candidates from a pool of ~400k items fast. Precision beats recall: every NEGATIVE in the golden set must be `reject`.

## Context
Every wrong photo in the v1 sample runs broke one of these rules (see `.orchestrator/recon/findings.md` "Root causes"): the item's dish type hidden in its menu category, a visual flavour word dropped, wrong protein/diet, combos. Text understanding lives in T03 (`studio/text.py`, `studio/lexicon.py`) — reuse it; never re-tokenize differently here.

## Contracts
- Consumes: T03 functions above; `rapidfuzz.fuzz`.
- Produces:
  - `class PoolIndex: __init__(self, items: Iterable[PoolItem] = ())`, `add(self, items: Iterable[PoolItem]) -> None`, `idf(self, token: str) -> float`, `retrieve(self, q: DishQuery, limit: int = 600) -> list[PoolItem]`, `__len__(self) -> int`, `item_tokens(self, item: PoolItem) -> frozenset[str]` (cached).
  - `score(q: DishQuery, item: PoolItem, idf: Callable[[str], float]) -> MatchScore`
  - `rank(q: DishQuery, items: Iterable[PoolItem], idf: Callable[[str], float]) -> list[Candidate]` — non-reject only, sorted by (tier order exact>strong>close, then text desc).
  - `same_dish_menu_match(q: DishQuery, items: Iterable[PoolItem], idf: Callable[[str], float]) -> Candidate | None` — best exact/strong candidate, else an item whose `fuzz.token_sort_ratio(normalize(q.display), normalize(item.name)) >= 92` with the same head (returned with tier "strong"), else None.
  - Tier text ranges: exact in [0.90, 1.0], strong in [0.75, 0.90), close in [0.55, 0.75), reject 0.0.

## Steps
1. Item token set = tokens(item.name) (T03). Item head = item_head(item.name, item.category, item.menu_name). Item proteins = item_proteins(item.name), or item_proteins(item.category) when the name has none. Cache per item_id/object id in PoolIndex.
2. `score(q, item, idf)` — evaluate against EACH variant in q.variants and keep the best result. Hard gates (any failure -> MatchScore("reject", 0.0, (reason,))):
   a. Empty variant or empty item tokens -> reject "empty".
   b. Diet: q.diet "veg" -> item.diet must be "veg"; q.diet "unknown" -> item.diet in ("veg","unknown"); q.diet "egg" -> item proteins == {"EGG"} and item.diet in ("egg","nonveg"); q.diet "nonveg" -> item.diet in ("nonveg","egg","unknown").
   c. Protein: q.proteins must equal item proteins (both empty is fine).
   d. Head: if q.head and item head and q.head != item head -> reject "head". If item head is set and q.head is None -> reject "item is a <HEAD>" UNLESS the item head token is literally in the variant. If q.head is set and item head is None and q.head not in item tokens -> reject "head missing".
   e. Combo: is_combo_name(item.name) and not q.is_combo -> reject "combo"; q.is_combo and not is_combo_name(item.name) -> tier at most "close".
   f. Tokens: let Q = variant tokens minus nonvisual; I = item tokens minus nonvisual. missing = Q - I; extra = I - Q.
      - any missing token with role in ("head","protein","base","visual") -> reject "missing <t>"
      - missing tokens all "soft" -> at most close
      - any extra token with role "base", "protein", "head" -> reject "extra <t>"
      - extra "visual" tokens: exactly one extra visual token whose idf is below the pool median idf -> at most close; otherwise any extra visual -> reject "extra <t>"
      - extra "soft" tokens -> at most strong
3. Tier: exact when missing and extra are empty (after nonvisual removal); strong when missing is empty and extras are only soft; close per the rules above. Text score = tier base (exact 0.90, strong 0.75, close 0.55) + up to 0.10 (exact/strong: 0.14 for close band cap to stay below next tier) from `fuzz.token_set_ratio(normalize(q.display), normalize(item.name))/100` weighted, minus 0.01 per nonvisual/soft extra; clamp inside the tier range.
4. `PoolIndex`: inverted index token -> list of item positions; df counts; N. `idf(t) = log((N + 1) / (df(t) + 1)) + 1` (unknown token -> max idf). `retrieve(q)`: collect items sharing tokens with any variant, prioritising rare tokens: for each variant take tokens sorted by df ascending, union postings of tokens with df <= 25% of N; always add postings of q.head if present (they may be many: cap to the `limit*3` rarest-overlap items); score candidates cheaply by weighted overlap (sum of idf of shared tokens) and return the top `limit` items. Pre-filter by diet gate. Must run < 50 ms for one query on a 400k-item index (build a 400k synthetic index in the perf test).
5. `rank(q, items, idf)`: score each, drop rejects, build `Candidate(item, score)`; sort; deduplicate by item.img_url keeping the best.
6. Put the golden set in `tests/test_matcher.py` as a module-level list `GOLDEN = [(dish_name, dish_category, item_name, item_category, item_diet, expected)]` where expected is "reject", "exact", "strong", "strong+" (exact or strong) or "close+" (exact, strong or close). Helper builds PoolItem(item_id=1, name=item_name, category=item_category, menu_name=item_category, description="", diet=item_diet, img_url="https://b.zmtcdn.com/x.jpg", res_id="1", res_name="R", res_url="https://www.zomato.com/pune/r", city="pune", chain_key="r") and uses a PoolIndex built from ~60 realistic items so idf is meaningful (or a constant idf of 5.0 where idf does not matter).
