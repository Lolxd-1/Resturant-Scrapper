## `orch.sh verify T13` result and root cause
`orch.sh verify T13` fails, but **not from anything in this task's Write-set**. The brief's own Verify block, line 2:
```
powershell -NoProfile -Command "$e=$null; ... if ($e.Count) { $e | ForEach-Object { $_.Message }; exit 1 } else { exit 0 }"
```
is executed by `run_block()` as one `bash` script. Inside bash double quotes, `$e`, `$null`, `$e.Count` all expand as (unset/empty) bash variables, and critically `$_` is bash's own special parameter (last argument of the previous command) — here it expands to the *entire previous line's python -c argument*, so the powershell `-Command` string bash actually sends is corrupted (verified this exact corruption text matches `orch.sh`'s log). This reproduces identically outside `orch.sh` (I built the same temp script and ran `bash script.sh`) and is independent of `scripts/setup.ps1`'s content — the same brief-authored line would break for any implementation. I did not (and per hard limits cannot) edit `.orchestrator/tasks/T13.md` to fix this.
I ran each of the three verify commands individually with correct bash quoting (single-quoting the powershell `-Command` string) and all three passed (see above), confirming `RUN_ME.bat`, `scripts/setup.ps1`, and `tests/test_server.py` all satisfy the brief's intent.
