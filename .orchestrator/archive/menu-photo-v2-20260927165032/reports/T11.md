# T11: Local web server (FastAPI) + app.py entry point

## Implemented
- `studio/server.py`: `create_app(engine_factory=None, *, output_dir=OUTPUT_DIR, config_path=CONFIG_PATH, start_worker=True) -> FastAPI`.
  - `Worker`: one daemon thread + `queue.Queue`; a separate daemon thread builds the `Engine` lazily via `engine_factory` (default wraps `build_engine(load_settings(config_path), on_status=...)`, mapping its two status callbacks to "Loading photo pool…" / "Preparing visual check (first run downloads ~600 MB)…", then "Ready"; failures set `status = f"Engine failed: {exc}"` and leave `engine=None`).
  - `EventBus`: per-job list of `(index, event)` capped at 5000 + a `threading.Condition`; SSE endpoint replays buffered events then polls `wait_for_more` via `asyncio.to_thread` (never blocks the event loop) with a 15 s keepalive, closing after a `done`/`error` event or when the job is inactive and the buffer is exhausted.
  - Photo-swap rebuild coalescing (T09/T10B note): `choose` calls `choose_alternate(..., rebuild=False)`, then `Worker.request_rebuild` enqueues a `("rebuild", job_id)` task (deduped via a `_rebuild_queued` set so repeated swaps before the worker gets to it only trigger one `rebuild_outputs` call) and clears a per-job `threading.Event`. `files/{kind}` and `zip` downloads call `Worker.wait_rebuild` first, which checks `job.json["sheets_stale"]` and waits on that event up to 90 s (falls back to a synchronous rebuild if the event is missing, e.g. after a restart).
  - Validation: job id regex `^\d{8}-\d{6}-[a-z0-9-]{1,40}$`, sku regex `^[A-Z0-9]{1,6}-\d{3,4}$`, file kind whitelist `{ready,pending,report}` — all 404 otherwise; job dirs are resolved and checked to stay inside `output_dir`.
  - Settings: GET/PUT never return or log a full key (only `tail = key[-4:]`); PUT keeps a stored key when `{"id":..}` has no/empty `"key"`, else validates `^[A-Za-z0-9]{20,64}$` (400 "That doesn't look like an ImgBB key" otherwise).
  - `GET /api/jobs` and `GET /api/jobs/{id}` report `status="interrupted"` (computed only, job.json untouched) when the stored status is `"running"` but the worker isn't currently processing/queuing that id.
  - All other endpoints per the brief's contract table (health, system, menu/preview with 10 MB/413 cap, jobs CRUD, cancel, resume with 409-if-active, choose, files/images/zip downloads with `Content-Disposition`, `/` serving `studio/web/index.html` with `Cache-Control: no-store`, `/static` mounted from `studio/web/`).
- `studio/web/index.html`: minimal placeholder page titled "Menu Studio" loading `/static/app.css` and `/static/app.js` (force-added past the repo's `*.html` gitignore rule per the brief's write-set).
- `app.py`: full v1 replacement. `main(argv=None) -> int` with `--port` (8501 default, walks forward to a free port), `--host`, `--no-browser`, `--self-test`. Logging configured `INFO`, format `"%(asctime)s %(message)s"`, datefmt `"%H:%M:%S"`. Single-instance detection via `home_dir()/"server.json"` + a 2 s `/api/health` probe; otherwise writes `server.json`, starts a polling thread that opens the browser once `/api/health` answers, prints the running banner, and calls `uvicorn.run(create_app(), ...)`. `--self-test` builds `create_app(start_worker=False)` (so it never touches the engine or the real config file), runs `uvicorn.Server` in a thread on a free port, GETs `/api/health` and `/`, prints `SELF-TEST OK`/`SELF-TEST FAILED`, and shuts the server down.

## Concerns
- `test_app_self_test` starts a real (ephemeral, background) uvicorn instance and takes a few seconds; it doesn't touch the engine or `config/settings.json` (`start_worker=False`), so it's safe to run repeatedly and offline.
- The rebuild-wait fallback (synchronous `rebuild_outputs` when a job's `sheets_stale` is true but no in-memory rebuild `Event` exists, e.g. right after a server restart) is untested — it's a corner case not covered by the listed test cases.

- `PoolStore.count_items()` / `count_restaurants()` already exist and are used directly for `/api/system`'s `pool_items`/`pool_restaurants`.
- The repo's `.gitignore` has a blanket `*.html` rule; `studio/web/index.html` had to be `git add -f`'d since it's explicitly in this task's write-set.
