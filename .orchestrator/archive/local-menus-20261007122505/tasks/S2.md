## Steps
1. lexicon.py `TOKEN_CUISINES: dict[str, tuple[str, ...]]` keyed by canonical tokens (as produced by text.tokens): kolhapuri, malvani, pitla/PITLA, BHAKRI, matki, misal, usal, kanduri, vajadi, rassa, sukka, tambda, pandhra, solkadhi, zunka, SHEVGA, BAJRA, JOWAR, RAGI -> ("maharashtrian",); hyderabadi -> ("hyderabadi","biryani"); HANDI, kofta, lababdar, KADAI, MAKHANI, lajawab, malai, shahi, kasuri, BUTTER, TIKKA, KEEMA, dahi (with protein) -> ("north-indian","mughlai"); MANCHURIAN, schezwan, CHILLI, NOODLES, FRIEDRICE -> ("chinese",); TANDOORI, KEBAB -> ("north-indian","kebab"); machhi/FISH/PRAWN -> ("seafood","maharashtrian"); dosa family already has heads. Use the exact canonical spellings text.tokens() returns (check with a quick python call).
2. pipeline.py search(): cuisines for a group = HEAD_CUISINES[q.head] when head is set, else the union (in order, deduped) of TOKEN_CUISINES for the tokens of variants[0], else the old default. Take the first 3 cuisines (was 2). The suggest query text = the CORRECTED dish text (the pipeline already has it from S1: use the same `fixed` string used for parse_dish; store it on the group).
3. zomato.py: `listing(city, cuisine, locality="")` builds `/{city}/{locality}-restaurants/{cuisine}` when locality is given (else unchanged). `localities(city)` fetches `https://www.zomato.com/{city}/restaurants` and returns unique locality slugs found by regex `/{city}/([a-z0-9-]+)-restaurants(?:[/"?]|$)` (exclude "delivery"/"best"/"new"), in page order, max 40.
4. tools/build_seed_pool.py: new flags `--localities N` (per city, 0 = off) and `--extra-cities a,b` (city slugs not in CITIES, e.g. kolhapur,satara,sangli,solapur; listing() works without an autoSuggest id). When --localities > 0, crawl `listing(city, cuisine, loc)` for the first N localities too. Keep resumability (skip restaurants already in the work DB).
