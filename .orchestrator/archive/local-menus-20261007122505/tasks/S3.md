# S3: Fix the 4 wrong Gavkari picks found by visual audit (veg imitation dishes, dish numbers, standalone "lachha")
Wave: 3 · Deps: S2 · Risk: high · Model: sonnet

## Goal
A veg dish is never shown with egg or meat, numbers that are part of a dish name ("Chicken 65") are kept, and a bare "Lachchha" on a bread menu is read as lachha paratha.

## Context — orchestrator audit of all 173 Hotel Gavkari picks (live, 2026-09-27), wrong ones:
- HG-031 "VEG ANDA KARI" (category "Shakahari Danka" = veg) -> picked "Anda Curry" (real egg curry). Kolhapuri "veg anda" is a paneer/potato imitation egg.
- HG-062 "VEG KHIMA" (category "Gavkari Special Shakahari Danka") -> picked "Keema" @ Hotel Madni Darbar (mutton keema).
- HG-109 "CHICKEN 65" -> picked "Ginger Chicken": the number 65 was dropped as noise, so only CHICKEN remained.
- HG-213 "LACHCHHA" (category "Churun Khayala", a bread section) -> corrected to "lachha", picked "Masala Lachha [200 Grams]" (a namkeen snack).

## Steps
1. Veg conflict (text.py parse_dish): if the dish has an explicit veg signal — a "veg"/"vegetarian"/"shakahari"/"jain" word in the NAME, or a veg hint in the CATEGORY while the category has no non-veg hint — AND its tokens contain a non-veg protein (EGG, KEEMA, CHICKEN, MUTTON, FISH, PRAWN, ...), then it is an imitation/veg-style dish: set diet "veg", proteins = frozenset(), and set a new DishQuery field `veg_imitation: bool = True` (add the field with default False to studio/models.py? NO — models.py is frozen: instead encode it by keeping the protein token in variants and relying on step 2). Keep the protein TOKENS in variants.
   Exception kept: KEEMA together with a base token (paneer/soya) stays veg without conflict (existing rule, "Paneer Kheema").
2. matcher.score diet/protein gate: when q.diet == "veg" and any variant contains a non-veg protein token, only an item that is diet "veg" AND contains that same protein token (e.g. a veg item named "Veg Anda Curry" / "Veg Keema") may match; everything else -> reject "veg imitation". (Item proteins for such veg items: treat a veg-diet item's protein tokens as imitation tokens: they must match the dish's tokens, not the protein-equality rule.)
3. Dish numbers (text.py tokens): a 2- or 3-digit number that is NOT inside parentheses and NOT followed by a unit word (ml, ltr, gm, g, kg, pcs, pc, piece(s), nos, inch, inches, " ) is kept as a visual token ("65", "555", "999"). Single digits and numbers in parentheses stay noise. Pool item names go through the same tokens(), so "Chicken 65" items carry "65".
4. Standalone bread words (spelling.py fix_text, applied to the WHOLE corrected name after word fixes): if the whole name equals "lachha" -> "lachha paratha"; "nan" already -> "naan". Add a small dict `WHOLE_NAME_EXPANSIONS = {"lachha": "lachha paratha", "laccha": "lachha paratha", "lachcha": "lachha paratha"}`.
5. Also add "lachchha" and "laccha" to MISSPELLINGS -> "lachha" if missing.
