# T08: ImgBB multi-key uploader — report

## Implemented

- `studio/hosting.py`: `IMGBB_URL`, `UploadError`, `Uploader`, module function `test_key`.
  - `Uploader.__init__` filters `keys` to those with `enabled=True` and a non-empty `key`,
    keeping per-key runtime state (label, key, tail = last 4 chars, disabled flag,
    cooldown_until, failure count, last_error). A single `_cursor` advances by one after
    every attempted key (success or failure), so consecutive `upload()` calls that each
    succeed on the first try use keys 1, 2, 3, ... in round-robin order.
  - `upload(jpeg, name)`: sha256-hex cache lookup via `store.get_upload` first (no HTTP on
    a hit); raises `UploadError("No ImgBB API key saved. Add one in Settings.")` if no
    usable keys; slugifies `name` to `[a-z0-9-]`, max 60 chars, for both the `name` form
    field and the uploaded filename. Scans keys from the cursor, skipping disabled and
    still-cooling keys; if every usable key is cooling down it sleeps until the earliest
    `cooldown_until` (capped at 120 s) and rescans. Total HTTP attempts are capped at
    `3 * len(keys) + 2`; when exhausted it raises
    `UploadError("All ImgBB keys failed: label: last_error; ...")` with no key material.
  - `_classify(resp)` centralizes response handling (shared by `upload` and `test_key`):
    network exceptions -> per-key cooldown `min(60, 5 * consecutive_failures)`; success
    (`success: true` + `data.url`) -> URL; `error.code == 100` or "invalid api" in the
    message -> key permanently disabled ("Invalid key"); status 429 or a rate/too-many/limit
    message -> 60 s cooldown; status >= 500 or a non-JSON body -> 10 s cooldown
    ("Server error <status>"); anything else (other 4xx, e.g. "Invalid image source") ->
    `UploadError` raised immediately without touching key state.
  - `_url_from_data`: prefers `display_url` when it starts with `http`, else falls back to
    `url`; upgrades a returned `http://` URL to `https://`.
  - `key_states()`: `{"label", "tail", "state": "ok"|"cooldown"|"disabled", "last_error"}`.
  - `test_key(key, *, http_post=requests.post)`: posts a generated 32x32 JPEG with
    `expiration=60`; maps outcomes to `(True, "Key works")`,
    `(False, "Invalid key")`, `(False, "Rate limited — try again later")`,
    `(False, "Could not reach ImgBB: <short>")` for network errors, else `(False, <message>)`.
  - No logger is used anywhere in the module, so no key values are ever logged; only
    label/tail/last_error strings appear in states and error messages.

## Tests added (tests/test_hosting.py)

All ten cases from the brief, using a small `ScriptedPost` fake callable (records the
`data` dict per call, raises/returns the next scripted item) and a `FakeClock`
(`sleep` advances `clock`) instead of real time:

- TC1: one key succeeds -> https `display_url`; `PoolStore` records the sha256 -> URL;
  a second upload of identical bytes makes zero HTTP calls; also asserts the slugified
  `name` field sent ("dish-name" from "Dish Name").
- TC2: 3 keys, 3 uploads of different bytes -> keys used in order k1, k2, k3.
- TC3: k1 returns the verified invalid-key JSON, k2 succeeds -> URL returned;
  `key_states()` shows k1 `"disabled"` / `"Invalid key"`; a later upload never calls k1 again.
- TC4: k1 returns 429 -> cooldown ("Rate limited"), k2 used; after the fake clock advances
  61 s, k1 is used again on the next upload.
- TC5: both keys invalid -> `UploadError` message contains both labels and no full key.
- TC6: network exceptions on both keys, then a wait (fake sleep advances the fake clock)
  lets the first key succeed on retry.
- TC7: "Invalid image source" (400, non rate/invalid-key) -> immediate `UploadError`;
  key state stays `"ok"` with empty `last_error` (key not blamed).
- TC8: one key empty, one key disabled via `enabled=False` -> `UploadError` with the exact
  Settings message.
- TC9: `test_key` mapped for success / invalid / rate-limit / network-error, and asserts
  the network-error message never contains the full key.
- TC10: a response `url`/`display_url` of `"http://..."` is returned as `"https://..."`.
