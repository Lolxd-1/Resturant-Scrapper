## Implemented (studio/pipeline.py)
- `Engine(store, vision, http, swiggy=None, gemini=None)`; `self.gemini` plain attribute. `build_engine` sets
  `Gemini(settings.gemini_key, cache_dir=ai_cache_dir())` when settings has a key, else None.
- `STAGE_LABELS["judge"] = "AI photo check"` (between verify and photos); `run.judge()` wired into run_job.
- `_Run.gemini` = engine.gemini if available, else None. `ai_failed(msg)` sets it to None, appends a warning and
  logs it. Any GeminiError stops Gemini calls for the rest of the job, with one warning.
- Enrich (`_Run._enrich`, called in `read()` right after `read_menu`): picks rows with empty diet or photo
  names and sends one call per 120 rows (ENRICH_SYSTEM/SCHEMA, max_output_tokens 32768). It fills only empty
  fields. Cleaning reuses `studio.reader._clean_item`, so diet, photo names and description get the reader's
  exact rules. It then logs "AI filled details for N dishes" (only when N > 0). On error the warning is
  "AI helper unavailable: {msg}".
- `_verify_group` stores `g.kept` (final sorted kept list, [] when nothing kept).
- `judge()`: skips failed groups and groups whose rows[0].source is own/chain. Candidates are `g.kept[:4]`.
  When kept is empty it uses the rescue set: rung-0 exact/strong candidates not marked bad, top 4. Groups go
  in batches of 25. Thumbnails are fetched in parallel (6 workers) and failed ones are dropped. Each call
  sends the exact parts from the brief (JUDGE_SYSTEM/SCHEMA, 16384). Dishes or labels missing from the answer
  keep A5's result.
- `_apply_verdicts`: ok = clean and verdict same/similar. Order: same first, then quality descending, then
  original order. used_images is handled like `_verify_group`: an unused ok candidate is preferred only if it
  has the same verdict, which mirrors the tier rule there. Outcomes:
  - "same" on rung 0, or on `g.option_rung` (per the ruling): ready (lookalike False, search_name "", reason "").
  - "similar" on rung 0: review, search_name = dish display, reason "Similar photo — approve it or search again".
  - Other rung >= 1: review (lookalike True, A5's search_name and reason kept).
  - No ok photo: the pick is cleared, with reason "AI found no matching photo (n checked)" or
    "AI found no matching look-alike photo (n checked)".
  - Alternates are the other ok candidates (at most 4).
- Logs "AI checked photos for K dishes" (K > 0). On error the warning is "AI photo check unavailable: {msg}".

## Concerns
- `_clean_item` is a private reader function imported into pipeline. I reused it rather than copy its cleaning
  rules. Making it public would need reader.py in a write-set.
- A rescued candidate (CLIP-vetoed) never had `c.final` set, so its confidence is 0.0 and the Photo Report and UI
  show 0%. The brief does not say what it should be.
- When the judge replaces or clears a group's A5 pick, the old image stays reserved for that group in
  used_images (same as `_verify_group`, which never releases). The only effect is slightly fewer fallback options
  for other dishes.
