# S2 report

## Implemented
- `studio/lexicon.py`: added `TOKEN_CUISINES` mapping canonical tokens (as produced by
  `studio.text.tokens`) to cuisine slugs to crawl when a dish has no head word — Maharashtrian
  words (kolhapuri, malvani, PITLA, BHAKRI, MATKI, MISAL, usal, kanduri, vajadi, CURRY (from
  rassa), sukka, tambda, pandhra, solkadhi, SHEVGA, BAJRA, JOWAR, RAGI), Hyderabadi/biryani,
  North Indian/Mughlai (HANDI, kofta, lababdar, KADAI, MAKHANI, lajawab, malai, shahi, kasuri,
  BUTTER, TIKKA, KEEMA, CURD), Chinese (MANCHURIAN, SCHEZWAN, CHILLI, NOODLES, FRIEDRICE),
  kebab (TANDOORI, KEBAB), and seafood (FISH, PRAWN — machhi already canonicalizes to FISH).
- `studio/pipeline.py`: `_cuisines_for(q)` returns `HEAD_CUISINES[q.head]` when a head is set,
  else the deduped union (in iteration order) of `TOKEN_CUISINES` for `q.variants[0]`'s tokens,
  else `DEFAULT_CUISINES`. `search()` now takes the first 3 cuisines (was 2) and builds the
  suggest query text from `g.q.raw` (the spell-corrected dish text already stored on the
  `DishQuery` from S1) instead of the raw menu row name.
- `studio/zomato.py`: `ZomatoClient.listing(city, cuisine, locality="")` builds
  `/{city}/{locality}-restaurants/{cuisine}` when a locality is given. New
  `ZomatoClient.localities(city)` fetches `/{city}/restaurants` and regex-parses unique
  locality slugs (excluding delivery/best/new), in page order, capped at 40.
- `tools/build_seed_pool.py`: `crawl()` gained a `localities: int = 0` parameter; when > 0 it
  fetches each city's localities once and additionally crawls `listing(city, cuisine, loc)` for
  the first N, sharing the same `seen_urls`/`menu_fetched_at` resumability the plain crawl uses
  (extracted the per-listing fetch loop into a local `fetch_batch` helper to avoid duplicating
  that logic). CLI: new `--localities N` and `--extra-cities a,b` flags; extra cities are
  appended to the crawl city list (`listing()`/`localities()` don't need a Zomato city id, so
  city slugs outside `CITIES` work unchanged).

## Discoveries
- `DishQuery.raw` already holds the speller's `fixed` text (set by `parse_dish(fixed, ...)` in
  `_Run.read`), so no new field was needed on `_Group` to "store" the corrected text — `g.q.raw`
  already is it.
- `retrieve()` in `studio/matcher.py` drops any query token whose posting list exceeds
  `n * 0.25` items *unless* the token is the dish's head (head postings bypass that cutoff).
  Any future live-search test for a headless dish needs >= 4 pool items total or it will always
  return zero candidates.
