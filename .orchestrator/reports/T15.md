# T15: Live evaluation tool (dry-run jobs + visual contact sheets)

## Implemented
- `tools/eval_menus.py`: CLI (`--menus DIR [--out DIR] [--only NAME] [--city pune] [--budget 250] [--strict]`,
  default out `eval/out`) that builds one `Engine` (`build_engine(load_settings())`) and, for each sorted
  menu file (`.xlsx`/`.xlsm`/`.csv`) in `--menus`, runs `run_job(..., JobOptions(upload=False, ...),
  uploader=None, on_event=<prints stage/log lines>)` into `out/<stem>`. Vendor name defaults to the file
  stem with `_` -> ` `; an optional `<stem>.json` sidecar can override `vendor`/`city`/`zomato_url`.
  After each job, reads `job_dir/results.json` and calls `contact_sheets` + `html_report`, then appends a
  summary row; writes `out/summary.csv` (menu, total, ready, needs_photo, needs_price, errors, coverage%)
  at the end.
- `contact_sheets(results, job_dir, out_prefix, per_sheet=20)`: 5-column grid of 300x300 tiles + a 90px
  caption strip (3 lines: SKU + dish name truncated 38, `-> item @ restaurant` truncated 44, `tier conf
  source`), grey "NO PHOTO: <reason>" tile when `local_image` is empty. Saves
  `<out_prefix>_01.jpg`, `_02.jpg`, ... at JPEG quality 85. Tries `arial.ttf` size 13, falls back to PIL's
  default font.
- `html_report(results, job_dir, out_path)`: self-contained HTML table (image `src` = `r.local_image`,
  relative to `job_dir` so it resolves correctly at `job_dir/review.html`), all text fields
  `html.escape`d.
- `.gitignore`: appended `eval/` so vendor menus and eval outputs are never committed.
