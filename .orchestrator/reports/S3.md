# S3 Report

## Implemented
1. **Veg-imitation conflict** (`studio/text.py`): `parse_dish` now runs `_veg_conflict(proteins, name, category)`
   after computing diet/proteins. It fires when the dish has a non-veg protein token AND a veg
   signal — "veg"/"vegetarian"/"jain"/"shakahari"/"shaakahari" in the NAME, or the same word in the
   CATEGORY with no non-veg hint there. On conflict, `diet` is forced to `"veg"` and `proteins` is
   cleared to `frozenset()`; the protein word stays in `variants` (untouched), so it can still be
   matched token-for-token against a genuine veg item ("Veg Anda Curry").
2. **Matcher gate for imitation dishes** (`studio/matcher.py`): `score()` no longer hard-rejects on
   `q.proteins != i_proteins` when `q.diet == "veg"` and a variant carries a non-veg protein token
   (reused the existing `NONVEG_PROTEINS` constant from `lexicon.py`, no new lexicon entries needed).
   In that case it falls through to the normal token/variant gate, which only accepts items whose
   tokens actually contain the same protein word — and since `_diet_ok` already requires the item to
   be `diet == "veg"` whenever `q.diet == "veg"`, non-veg items are still rejected earlier.
3. **Dish numbers** (`studio/text.py`): added `_kept_numbers()`/`_KEEP_NUM_RE`, which strips parens
   content out of the raw text first, then finds 2-3 digit numbers not immediately followed by a
   unit word (ml, ltr, gm, kg, pcs, pc, piece(s), nos, inch(es), etc.). `_is_noise` now keeps such
   numbers as visual tokens instead of always treating digits as noise; single digits and numbers
   inside parentheses are unaffected (still dropped).
4. **Standalone bread word** (`studio/spelling.py`): added `WHOLE_NAME_EXPANSIONS` (`lachha`/`laccha`/
   `lachcha` -> `"lachha paratha"`), applied in `Speller.fix_text` to the fully corrected name.
   Added `"laccha": "lachha"` to `MISSPELLINGS` (`"lachchha"` was already present).

`studio/lexicon.py` needed no changes — the required `NONVEG_PROTEINS` constant already existed.

## Concerns
- The brief's HG-062 example name is "VEG KHIMA" (raw, pre-spelling-correction). `parse_dish` in
  the matcher GOLDEN test is called directly on the raw string without `Speller.fix_text` (as all
  other GOLDEN rows are), so "khima" never becomes the canonical "KEEMA" protein token there — it
  would just be an unrelated visual token, and the reject would happen for the wrong reason (token
  mismatch, not protein/diet conflict). I used "Veg Keema" instead so the test actually exercises
  the veg-imitation gate. In production, dish names go through `Speller.fix_text` before
  `parse_dish`, so the real pipeline handles "VEG KHIMA" correctly — this is purely a test-input
  choice to match how the rest of the GOLDEN table is written (already-corrected spelling).

## Discoveries
- `lexicon.py` already exported `NONVEG_PROTEINS = frozenset(PROTEINS.values())`, so no new lexicon
  constant was needed for the matcher's veg-imitation check.
- `DIET_HINTS_VEG` includes "paneer", which the brief's veg-conflict signal deliberately excludes
  (only veg/vegetarian/jain/shakahari/shaakahari) — used a separate, narrower word set in text.py
  to avoid false positives like a paneer-named dish that also happens to carry a stray protein word.
