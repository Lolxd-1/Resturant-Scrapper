## Implemented

- `studio/sheets.py` (new):
  - `safe_vendor(vendor)`: strips to `[A-Za-z0-9_]`, collapses runs to one `_`, strips
    leading/trailing `_`, truncates to 40, falls back to `"Vendor"`.
  - `category_for(r)`: `r.category.strip()` or `"Menu"`.
  - `build_outputs(results, template, out_dir, vendor, *, vision_on=True) -> dict[str, Path]`:
    sorts by `row`; `ready = status == "ready"`, `pending = everything else`; for each of
    READY/PENDING: `shutil.copyfile(template, dest)`, `openpyxl.load_workbook(dest)`
    (not read_only), writes rows contiguously from row 2 into `bulk_upload_template`
    (C sku, D name[:200], E/F price, G "FOOD_AND_GROCERY", H category[:100],
    I description[:2000] or None, P hosted_url or None), save, close. Then builds the
    report workbook (`Summary`, `Dishes`, `Owner photo checklist`) and returns the three
    paths, creating `out_dir` if missing.
  - Prices: `int` when whole, else `round(x, 2)`; `None` stays `None` (blank cell) so PENDING
    rows without a price leave E/F empty.
  - All strings run through `ILLEGAL_CHARACTERS_RE.sub("", s)` (from
    `openpyxl.cell.cell`) before being written, so control chars like `\x07` are dropped;
    normal unicode (Devanagari, `₹`, emoji) passes through untouched.
  - Report `Dishes` sheet: 13-column header, friendly status via `STATUS_LABELS`,
    confidence as `round(confidence*100)`, `Restaurant link`/`Photo link` written with
    `cell.hyperlink` set to the URL text (via a `_set_link` helper), bold+frozen header,
    auto-filter, per-column widths (Dish 38, Reason 40, both link columns 30, others
    12–18).
  - `Owner photo checklist`: only `needs_photo` rows, fixed "How to shoot" string.
  - `Summary`: label/value rows including `Photo coverage` =
    `round((ready + needs_price-with-hosted_url) / total * 100)` as `"NN%"`, and
    `Visual check` = `"On"`/`"Unavailable"` from the new `vision_on` keyword-only arg
    (the one permitted contract extension).

## Discoveries

- `data/smartbiz_template.xlsx`'s `bulk_upload_template` sheet is 27 MB of XML (`~49,000`
  rows × ~21 columns, almost every cell pre-styled) and this venv has no `lxml` (pure
  Python `xml.etree` backend). Measured on this machine (repeatable, cProfile-verified —
  `bind_cells` instantiates ~1.15M `Cell` objects):
  - `openpyxl.load_workbook(copy_of_template)` (not read_only): **~6.2 s**, fixed cost
    independent of how many rows are later written.
  - `wb.save(...)`: **~9.4–9.8 s**, same fixed cost (verified unaffected by write count,
    and unaffected by forcing `ZIP_STORED` instead of `ZIP_DEFLATED` — the cost is XML
    object construction, not compression).
  - Two full independent load+save cycles (one per output file, as the brief's Steps
    literally describe): **~33–35 s measured in pytest** (my ad hoc benchmark outside
    pytest: ~31 s).
  - Best-case optimization (load once, write+save READY, clear+write+save PENDING from
    the same in-memory workbook, skipping the second `shutil.copyfile`+load): **~26 s**
    (still over the 20 s budget). `copy.deepcopy(wb)` as an alternative to a second load
    is *slower* than reloading from disk (~24.7 s for the deepcopy alone).
  - No dependency-free way found to get under 20 s while still using non-read-only
    `openpyxl` to parse+rewrite the full real template twice.
- This is orthogonal to my code: an empty `build_outputs` that immediately called
  `openpyxl.load_workbook` + `save` twice on copies of the real template would show the
  same floor.
