# T05 report: Pool store (SQLite)

## Implemented
`studio/store.py`: `PoolStore` — thread-safe SQLite-backed pool of every fetched menu, an
upload cache (sha256 -> hosted URL), an image-embeddings cache (float32 blobs), and a
bad-image cache. Single connection (`check_same_thread=False`, WAL, synchronous=NORMAL),
one `threading.RLock` around every public method/transaction.

- `ensure_seeded(seed_path)`: signature-gated (`size:mtime_ns` in `meta.seed_sig`) one-time
  import of the gzip JSONL seed pool; groups lines by restaurant, skips restaurants already
  present with `source='live'`, skips malformed lines, batches inserts 5000 rows at a time,
  returns item count inserted (0 on missing file or matching signature).
- `upsert_menu(menu)`: upserts the restaurant row (`fetched_at=time.time()`, `source='live'`),
  deletes then re-inserts its items in one transaction; empty item list still records the
  restaurant row so it isn't re-fetched immediately.
- `all_items()` joins items+restaurants into `PoolItem`s, in-memory cached, invalidated on
  every write (`upsert_menu`, `ensure_seeded`).
- `get_embedding`/`put_embedding` store/read `np.float32` bytes + dim; `get_upload`/
  `put_upload`, `mark_bad_image`/`is_bad_image` are simple keyed caches.
- `menu_fetched_at(res_url)` canonicalizes via `studio.zomato.canonical_res_url` and returns
  `0.0` for seed rows, the real timestamp for live rows, or `None` if unknown.
- Restaurant `chain_key` reuses `studio.zomato.chain_key(name)`.

## Tests added (tests/test_store.py, 10 tests covering TC1-TC9)
- `test_tc1_upsert_menu_and_all_items` — full PoolItem field shape + counts.
- `test_tc2_upsert_menu_replaces_items` — second upsert replaces items, no dupes, fetched_at advances.
- `test_tc3_ensure_seeded` — 3-restaurant gzip JSONL, a live restaurant untouched by seed, a
  malformed line skipped, second call returns 0.
- `test_tc3_ensure_seeded_missing_file` — missing seed path returns 0.
- `test_tc4_uploads` — unknown -> None; put then get round-trips.
- `test_tc5_embeddings_roundtrip` — 512-dim float32 vector, `np.array_equal` exact round-trip.
- `test_tc6_bad_images` — mark/is_bad_image, unknown stays False.
- `test_tc7_unicode_roundtrip` — Devanagari + emoji + accented text in name/description/res_name.
- `test_tc8_thread_safety` — 4 threads x 25 upserts concurrently -> `count_restaurants() == 100`, no exceptions.
- `test_tc9_reopen_sees_previous_data` — new `PoolStore` on the same path sees prior writes.

## Self-review
- Diff limited to the two Write-set paths (`git status --porcelain` confirmed clean otherwise).
- No new dependencies (numpy already locked in requirements.txt for the CLIP models used later).
- Reused `canonical_res_url`, `city_of` (implicitly via stored `city` on PoolItem), and
  `chain_key` from `studio.zomato` rather than reimplementing.
- Batch size fixed at 5000 per the brief; both restaurant and item inserts are chunked during
  seeding (brief only required it for items; chunking restaurants too is harmless and cheap).

## Concerns
- `ensure_seeded` isn't benchmarked against a real 400k-line file in this test suite (the
  brief's ~60s target); logic is O(n) with batched executemany so it should scale, but this
  is not empirically verified here. Building/consuming that large fixture is T14's job.

## Discoveries
- `RestaurantMenu` doesn't carry a `chain_key` field itself (only `PoolItem` does); the store
  computes it directly via `chain_key(menu.name)` for the `restaurants` table row.
