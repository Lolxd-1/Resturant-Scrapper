## Implemented
- `studio/lexicon.py` (data only, dicts built by comprehension): SYNONYMS (from `_SYNONYM_GROUPS`), PHRASES, NOISE, NON_VISUAL, SOFT, HEADS, HEAD_GROUP, HEAD_PROMPT, HEAD_CUISINES, PROTEINS, NONVEG_PROTEINS, COMBO_WORDS, CATEGORY_HEAD_HINTS, DIET_HINTS_NONVEG, DIET_HINTS_VEG. v1 mistakes are not carried over: bharwa, besan, kulcha, bhakri, vada and chaap each keep their own token, and peri/dum/tulsi/adrak are no longer dropped.
- `studio/text.py`: normalize, tokens, token_role, item_proteins, is_combo_name, item_head, size_base_key, parse_dish.
  - Token pipeline: normalize -> PHRASES (longest first, whole-word, one pass) -> per word: drop noise (digits, single letters, NOISE incl. singular form) -> canon (exact SYNONYMS lookup, then singular lookup, else singular). Deduped, order kept. If the result is empty, it falls back to the unfiltered words (only for tokens()/main name).
  - Parentheticals: content with "/" becomes option variants (main + option). Otherwise the content is an alias variant when it has a head/protein token or >=2 visual/base tokens, and is appended to the main variant as modifiers when it does not. Variants are deduped; variants[0] is always the main.
  - Head: last head token of the main text. For combos it is the first segment (split on and/plus/with) that has a head. If the main text has no head, the first parenthetical with a head is used.
  - item_head falls back to category, then menu_name, via CATEGORY_HEAD_HINTS (plural s/es allowed). It returns a head only when exactly one hint matches and no generic word matches. Generic words are keys with value "": bread, beverage, drink, dessert, snack, starter, combo, meal, ...
  - Diet: nonveg if any non-EGG protein or a nonveg hint in name/category. Otherwise egg if EGG. Otherwise veg if a veg hint. Otherwise unknown.

## Self-review / deviations (all additive)
- The alias rule counts only visual/base tokens toward ">= 2 non-noise tokens". This is needed so that the brief's own example "(Kala Masala Special)" stays a modifier, since masala is soft.
- "/" options are handled as separate variants. This is needed for the brief's "(Veg/Paneer)" example, where main stays {STEAM,MOMOS}.
- KEEMA stops being a protein when a base token (PANEER, SOYA, ...) is present, so "Paneer Kheema" is veg rather than nonveg.
- Fish species (pomfret, surmai, bangda, bombil, ...) stay distinct lowercase tokens, with PROTEINS -> FISH. The brief allowed either reading; this one avoids collapsing visually different fish.
- Extra lexicon entries:
  - "plus" and "or" in NOISE.
  - PROTEINS: BOILEDEGG and OMELETTE -> EGG, plus PORK and BEEF.
  - A new head ICEDTEA (drink_glass), with "iced tea"/"ice tea" phrases, so iced tea is not grouped with hot tea.
  - Phrases: MIXVEG, "green peas" -> MATAR, "lady finger" -> BHINDI, "gram flour" -> BESAN, "chow mein", "nimbu pani", "sweet corn".
  - Synonyms: SCHEZWAN group, PAV, fritter(s) -> PAKODA, BHAJI covers sabzi/sabji/subzi.

## Concerns
- The brief's diet rule checks category nonveg hints before name veg hints. A veg item inside a category like "Veg & Non Veg Starters" therefore becomes nonveg, and "Egg Biryani" under "Non Veg Biryani" also becomes nonveg. I implemented the rule as written; a name-first order would be safer.
- CATEGORY_HEAD_HINTS uses the value "" to mark generic words. Consumers should look hints up only through item_head().
- "Veg Keema" (no base token) is still nonveg, because "veg" is noise.

## Discoveries
- parse_dish(...).head and item_head(name) share one head function, so pool items and menu dishes get heads the same way. Size words also appear in base_key only after normalize: base_key is a normalized lowercase string, not tokens.
- The token-role base set is the private `_BASES` in text.py. Use token_role() to access it.
