# T10B: Photo swap (choose_alternate) + headless CLI

## Implemented
- `studio/pipeline.py`:
  - `choose_alternate(engine, job_dir, sku, alt_index, uploader, *, rebuild=True) -> DishResult`
    - `alt_index=None`: inserts the current pick at `alternates[0]`, clears
      `local_image`/`hosted_url`/`zomato_img`, sets status `needs_photo` with
      reason "Marked by you: needs owner photo".
    - `alt_index=int`: looks up `alternates[alt_index]` (IndexError ->
      `ValueError("No such alternate")`), downloads it via `imaging.fetch_full`
      (`None` -> `ValueError("That photo could not be downloaded")`), saves
      `images/<sku>.jpg`, uploads when the job's `options.upload` is True and an
      `Uploader` was given (`UploadError` -> `ValueError` with its message),
      puts the previous pick back into `alternates` in its place (or drops the
      slot if there was no previous pick), updates the pick fields, and
      recomputes status via the existing `_settle` helper.
    - Unknown SKU -> `ValueError(f"Unknown SKU {sku}")`.
    - Always rewrites `results.json`; when `rebuild=True` calls
      `rebuild_outputs(engine, job_dir)`; when `rebuild=False` only sets
      `job.json["sheets_stale"] = True`.
  - `rebuild_outputs(engine_or_none, job_dir) -> dict`: reloads `results.json`,
    calls `sheets.build_outputs`, writes the refreshed summary into `job.json`
    and clears `sheets_stale`. Accepts `engine_or_none=None` (falls back to the
    previous summary's `vision` flag) for UI callers that only need to redo the
    sheets.
  - Small refactor: extracted the summary-dict computation from `_Run.summary`
    into a module-level `_summarize()` so `rebuild_outputs`/`choose_alternate`
    reuse the exact same shape; `_Run.summary` now delegates to it (behavior
    unchanged, verified by the full existing `test_pipeline.py` suite).
  - Added `_pick_dict(r)` (mirrors `_cand_dict` but for a `DishResult`'s current
    pick) used by both branches of `choose_alternate`.
- `zomato_scrapper.py`: replaced the whole v1 file with a thin CLI (`main(argv=None) -> int`)
  over `studio.pipeline` (`build_engine`, `run_job`, `load_job`, `new_job_id`,
  `JobOptions`) and `studio.hosting.Uploader`. Uploader keys come from
  `Settings.imgbb_keys`, else `IMGBB_API_KEY` env var as one key labelled
  `"env"`; `--no-upload` forces `uploader=None` and `opts.upload=False`.
  `build_engine` is called as `pipeline.build_engine(...)` (module-qualified)
  so tests can monkeypatch `studio.pipeline.build_engine`. Stage/dish/log/error
  events are printed; the three output file paths and the summary dict are
  printed at the end; exit 0 iff `job.json["status"] == "done"`. Forces UTF-8
  stdout via `sys.stdout.reconfigure(...)` when available.

## Tests added (`tests/test_pipeline_cli.py`)
- `test_choose_alternate_swaps_photo_and_rebuilds` (TC1): runs a TC1-style job
  (two pool restaurants both matching "Cheese Pizza"), backdates the
  UPLOAD_READY sheet's mtime, calls `choose_alternate(sku, 0)`, and asserts
  `zomato_img` swapped to the alternate, the old pick is now in `alternates`,
  status stays `ready`, the sheet's mtime advanced, and column P holds the new
  hosted URL.
- `test_choose_alternate_mark_needs_photo` (TC2): `choose_alternate(sku, None)`
  -> status `needs_photo`, reason set, image fields cleared, old pick kept as
  an alternate, row moved from UPLOAD_READY to PENDING.
- `test_choose_alternate_errors` (TC3): unknown SKU and out-of-range
  `alt_index` (99) both raise `ValueError`.
- `test_cli_no_upload` (TC4): monkeypatches `studio.pipeline.build_engine` to
  return a fake `Env` engine; `main([...--no-upload...])` returns 0, the three
  `.xlsx` files exist, and stdout contains "UPLOAD_READY".
- `test_cli_bad_file` (TC5): a corrupt `.xlsx` -> `main()` returns 1 and stdout
  contains the menu read error ("Could not open the file").
