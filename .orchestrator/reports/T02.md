# T02 report: Menu reader (any vendor Excel/CSV -> MenuParseResult)

## Implemented
`studio/menu.py`:
- `parse_price(value)` — int/float (NaN or <=0 -> None); str: strips ₹/Rs/Rs./INR/`/-`/commas/
  spaces (case-insensitive) then takes the first `\d+(?:\.\d+)?` match; no match or <=0 -> None.
- `clean_category(text)` — collapses whitespace, strips surrounding `-:|* `, title-cases all-upper/
  all-lower text (mixed case left alone), truncates to 100 chars.
- `derive_sku_prefix(vendor)` — tokenizes `[A-Za-z0-9]+(?:'[A-Za-z]+)?`; one word -> first 3 alnum
  chars upper; 2-3+ words -> first letter of first 3 words upper; sanitized to A-Z0-9, max 6,
  fallback `"SKU"`.
- `read_menu(path)` — never raises (all file I/O wrapped in try/except):
  - `.xls` -> guidance error; unsupported ext -> error; `.csv` read via `csv` module
    (utf-8-sig then cp1252 fallback); `.xlsx`/`.xlsm` via `openpyxl.load_workbook(data_only=True,
    read_only=True)`.
  - For xlsx, every worksheet (first 2000 rows) is parsed independently; the sheet producing the
    most dish rows wins (ties -> first sheet).
  - Header detection scans the first 15 rows for a role-synonym match (name + price/category);
    falls back to the v1 layout (name=0/category=1/description=2/price=3, `header_row=0`) when the
    first non-empty row's column 3 looks like a price or column 1 is text, with a warning.
  - Section-header rows (name only, no price/description/category, next non-empty row has a
    price) become the running category instead of a dish row.
  - Category resolution order per dish: own cell -> current section -> last non-empty dish
    category above it -> `""`.
  - Duplicate (case-insensitive name, same category) keeps both rows, flags the second.
  - File-level warnings for "no header row", missing-price count, and missing category column;
    `errors=["No dishes found..."]` when nothing parses.

## Concerns
- The header-less fallback's "upgrade to v1 layout" condition (first non-empty row: col3 parses as
  a price OR col1 is text) is under-specified for the case where neither holds — I left `columns`
  as `{"name": 0}` only in that case (no warning), since no test case exercises it and the brief's
  wording focuses on the case that does (TC11).

## Discoveries
- Real vendor xlsx rows can have fewer trailing cells than the header (openpyxl read-only trims
  trailing all-blank cells), so `_cell()` must bounds-check `idx < len(row)` rather than assuming a
  uniform row width — confirmed via the Ganesh file's "Shrikhand"/"Lassi"/"Aamras" rows (3-tuple,
  no price cell at all).
