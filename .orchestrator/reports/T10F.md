# T10F Report

## Implemented
1. `studio/sheets.py`: `_write_rows` and `_clear_rows` now set `.value` on the cell object
   (`ws.cell(row, column).value = v`) instead of passing `value=` to `ws.cell()`, which
   openpyxl silently ignores when the value is `None`. This was why PENDING rows kept a
   prior READY row's photo/description (openpyxl's `cell(value=None)` is a no-op both for
   clearing and for writing `None`).
2. `studio/store.py`: `items_for_restaurant` now runs a single scoped SQL query
   (`... WHERE i.res_url = ?`) joined against `restaurants`, building `PoolItem`s directly
   from the row, instead of calling `all_items()` (which rebuilds/caches the full item list).
   `upsert_menu` is untouched (it still invalidates `_items_cache`; that cache is only
   rebuilt when something calls `all_items()`).
3. `studio/pipeline.py`: `Engine.blocked` is now a read-only property computed from a new
   `blocked_until: float = 0.0` timestamp (`time.monotonic() < blocked_until`). `_Run._blocked`
   sets `blocked_until = time.monotonic() + 1800` instead of `blocked = True`. `run_job` logs
   `"Live search paused for N more minutes (Zomato limited this PC)"` at the start of a run
   when `engine.blocked` is still true. Confirmed `Engine.add_menu` never calls
   `store.all_items()` (it only calls `items_for_restaurant`, per fix #2).

## Discoveries
- `Http.get` retries 403s `max_retries + 1` (5) times before raising `ZomatoBlocked`, and
  FakeSession's queued-response semantics only pop items while the queue has >1 entries (a
  1-item queue repeats forever). Any future test that wants a Zomato block to fire exactly
  once (then behave normally) must queue at least 5 blocking responses before the
  fall-through response.
